# Области проверок и тестовое окружение

Общий pytest и runner теперь собирают тесты от корня проекта: приложение и
harness по действующим правилам pytest. Автоматический общий сбор пропускает
только два inbox-дерева — harness/common/inbox и harness/project/inbox, сохраняя
стандартные исключения окружений и служебных каталогов. Активные before,
candidate и source вне этих деревьев не являются архивными исключениями.
Runner запускает один общий процесс pytest, а не каждую историческую редакцию.

Явный файл или каталог кандидата/снимка остаётся целевой областью проверки.
Смешанный root+inbox запуск имеет фактический состав, зависящий от pytest и hooks;
он не даёт гарантии ни исключения соседних редакций, ни полноты общего прогона.
pytest выбирает один конфиг; вложенные настройки не объединяются автоматически.
Пользовательские форматы, шаблоны обнаружения, маркеры и плагины сохраняются.
Эти настройки управляют сбором, но не защищают файлы от намеренного изменения.

Переносимый основной набор использует pytest без обязательных сторонних
плагинов. requirements.txt фиксирует прямые зависимости; requirements.lock —
результат `uv pip compile --universal --python-version 3.9` с условными
зависимостями платформ и версий Python. Coverage нужен для сравнения покрытия
миграций. Тестовое окружение не требуется стартовому checker.

Команды, выбор области, настройка окружения и интеграция конфигурации принадлежат
[testing.md](../skills/comm-install-harness/references/testing.md).
Это объяснение механизма и состава, не самостоятельный владелец процедур.
