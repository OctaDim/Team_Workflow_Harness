# Установка переносимой защиты входов

Принято пользователем 2026-10-05: проверки с предупреждением при обнаружении правки и блокировкой проверяемого коммита. [Поведенческий контракт](../rules/comm-user-owned-entrypoints.md) запрещает прямые изменения обоих файлов пользователям и агентам; изменение содержания проходит согласованную обработку inbox. Автоматическое восстановление стартовых ссылок — отдельное разрешённое исключение.

## Граница защиты

Согласованная начальная версия AGENTS.md и CLAUDE.md хранится в Git HEAD. Проверка сравнивает с ней содержимое рабочей копии или индекса. В AGENTS.md допускаются только восстановленные стандартные строки ссылок, включая их порядок и конечные пустые строки; другие настройки сохраняются. CLAUDE.md обязан содержать только @AGENTS.md с необязательным конечным переводом строки.

Нельзя исправлять нарушение автоматической заменой пользовательского текста или ослаблением проверки. Сообщение направляет в `harness/<пакет>/inbox/`. После утверждения конкретной заявки её применение и обновление согласованной Git-версии требуют отдельной процедуры: эта проверка не разрешает изменения по одному наличию файла заявки. Универсальный механизм такого применения пока не разработан. Не обходить отказ собственного гейта через `--no-verify`.

Проверка обнаруживает уже записанную правку; она не предотвращает запись редактором. Локальный hook не защищает от его отключения, изменения HEAD или обхода Git. Это выбранная переносимая граница, а не защита средствами ОС.

## Первоначальное подключение

Нужны Python 3.9+ и Git. Сначала проверить согласованный статичный вход и зарегистрировать его начальную версию в Git отдельным разрешённым коммитом. Автоматически принимать произвольное текущее содержимое как новое основание запрещено. Без начальной регистрации команда восстановления сообщает, что защита ещё не активирована, а отдельная защищающая проверка завершается ошибкой.

Из корня проекта:

```sh
python3 -B harness/common/checks/ensure_entrypoint_links.py --check-protected
python3 -B harness/common/checks/ensure_entrypoint_links.py --check-protected --staged
```

Обе команды только читают. Первая проверяет рабочую копию, вторая — реальные файлы индекса, даже если рабочий файл после staging уже восстановлен.

Образец hook: [pre-commit](../checks/pre-commit). Git запускает его из корня проекта; команды установки для обычного репозитория без настроенного hooksPath:

```sh
install -m 755 harness/common/checks/pre-commit .git/hooks/pre-commit
```

Перед установкой проверить `git config --get core.hooksPath` и существующий hook. Не заменять чужую цепочку проверок; добавить вызов в действующий hook или отдельно согласовать установку. Для Git worktree путь hook нужно определить через `git rev-parse --git-path hooks/pre-commit`; команда с `.git/hooks/` там неприменима. Не заявлять, что hook включён, лишь по наличию образца внутри harness.

## Восстановление и диагностика

```sh
python3 -B harness/common/checks/ensure_entrypoint_links.py
```

При согласованной версии HEAD сначала проверяется неизменность настроек. Затем сообщение о повреждении выводится с flush до записи восстановленных ссылок. Неповреждённый вход не вызывает сообщения о повреждении. Нарушение в другом тексте останавливает восстановление; файл не переписывается и не становится новой согласованной версией.

Проверка временных проектов:

```sh
python3 -B harness/common/checks/test_ensure_entrypoint_links.py
python3 -B harness/common/checks/test_entrypoint_protection.py
```

## Ограничение текущей установки

Скрипт и образец hook сейчас находятся в common. Common-only и совместный режим имеют доступ к ним. Project-only пока не содержит собственной проверки, а исходный шаблон требует common; независимость project-only не доказана. Способ устранения требуется согласовать, не отменяя требования независимости и запрета дублирования знаний.
