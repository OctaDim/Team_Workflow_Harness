# Проверка вызова скиллов плагинов в Codex CLI

20 ноября 2026 года. База `570075a`. [Кандидат](candidate-v1/comm-validate-harness-instructions/SKILL.md).

Процедура принадлежит существующему скиллу проверки. Она нужна только при вопросе о вызове по имени. Условная ссылка даёт доступ к деталям без постоянной загрузки. Отдельное правило увеличило бы стартовую загрузку, а сочетание правила и скилла потребовало бы раннего ограничения, которое для этой проверки не нужно.

## Живые вызовы плагинных скиллов

Codex CLI 0.166.0. Профиль по умолчанию, без `-p` и переопределения модели. Рабочий каталог всех трёх вызовов и снимков каталога — `/tmp/inbox04-live.zxzQzDao/workspace`, пустая учебная папка без harness. Каждый запуск использовал `codex -a never exec --ephemeral --skip-git-repo-check --sandbox read-only -C <cwd> --json <запрос>`. Каталог получен через `codex app-server --listen stdio://`, запрос `skills/list` с тем же `cwd` и `forceReload`.

Перед серией зафиксированы SHA-256 настроек, включённые плагины и версии в кэше. Пара снимков подтверждающей серии совпала побайтно. В выдаче было 139 записей до и после, без ошибок. При первом запуске из песочницы App Server не открыл SQLite в профиле. С временной SQLite-базой возникла следующая ошибка `Read-only file system (os error 30)`. Живые прогоны прошли вне родительской песочницы с обычным профилем. Первую серию повторили после смены версий двух посторонних плагинов между снимками.

Код выхода во всех трёх случаях — 0. Сверка сопоставила полное содержимое успешного события чтения с файлом соответствующего владельца. У первого результата подтверждены запись каталога, явный вызов и применение. Для второго подтверждён вызов через кэш. Доступность инструментов плагинов в этих прогонах не проверялась.

Исходные JSONL, запросы, коды выхода и снимки серии сохранены локально в `/tmp/inbox04-live.zxzQzDao`. Номера строк в таблицах отсчитываются с единицы.

## Поведение кандидата в harness

Каждый режим проверен в отдельной временной установке. Штатная команда `python3 -B harness/common/checks/ensure_entrypoint_links.py` прошла дважды. В common-only создан нейтральный project. В common+project входные и итоговые SHA-256 файлов project совпали. Нативный каталог показал ровно одну включённую запись скилла из `.agents/skills` в каждом режиме. Каноническая копия, которую читали диалоги, совпадала с нативной.

В исходной версии на том же явном запросе Codex отделил факт наличия файла от доступности. Ответ не назначил отдельный запуск в том же профиле для каждого имени и не предусмотрел контрольные случаи. В четырёх профильных диалогах с кандидатом Codex открыл условный ресурс, описал отдельные запуски и контрольные случаи, потребовал свидетельства загрузки и применения. В двух посторонних запросах ответил «195 секунд» без чтения скилла или его ресурсов.
