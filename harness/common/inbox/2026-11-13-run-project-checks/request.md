## Согласованный контракт

R1. Выбирать проверки по затронутому контракту и последствиям: вызовы, общие фикстуры, конфигурация и зависимости, а не только список изменённых файлов. Использовать штатный runner/configuration целевого проекта, не навязывать EPL pytest_diff или иной стек.
R2. Подтверждать сбор и достаточность охвата. Пустая выборка и зелёная узкая выборка сами по себе не доказывают достаточность. Перед завершением выполнять весь релевантный набор, включая существующие тесты.
R3. Политика А действует ТОЛЬКО для кода и файлов приложения: явный запрос пользователя полного прогона разрешает его без повторного подтверждения; при обычной задаче агент выбирает достаточные релевантные проверки, а необходимый полный прогон объясняет и согласовывает. Обязательные проверки, ограничения проекта и доступов сохраняются. Для harness остаются его собственные процедуры и разрешения.
R4. Проверяемая версия стабильна; нет параллельной мутации общего дерева или смены исходников. Перед перезапуском проверить живой процесс; молчание лога не равно зависанию. Сбор/dry-run не равен выполнению.
R5. Сохранить фактическое завершение runner, код возврата и выполненные результаты. Успех обёртки, обрезанный хвост или произвольная строка summary не являются достаточным доказательством.
R6. Разделять дефект поведения/теста, ошибку сбора/импорта, среду и нестабильность. Если для атрибуции нужно сравнение, повторить те же падающие случаи в изолированной baseline-версии. Не править код, зависимости или системные настройки только для зелёного результата; новые полномочия не следуют из диагностики.
R7. Отчёт: команды, версия/среда, реальный выполненный охват, результаты, пропуски и невыполненные/непокрытые случаи с причинами. Успех тестов не гарантирует отсутствия всех ошибок. Общая проверка фактов, причинный ремонт и сохранение evidence не дублируются.

## Сценарии будущего исполнения — сейчас не запускались

- Изменена общая фикстура/конфигурация: учесть зависимых потребителей, не ограничиться новым тестом.
- Пустая diff-выборка либо только dry-run: не считать тесты выполненными.
- Явный полный прогон приложения: запуск без повторного подтверждения в пределах доступов.
- Необходим полный прогон без явного запроса: объяснить и согласовать перед ним.
- Запрос полного прогона harness: не применять политику А; использовать отдельные требования harness.
- Пайп/wrapper зелёный, runner не завершился либо есть лишь строка passed: не заявлять успех.
- Параллельный отчёт неполон: сравнить те же реальные падающие случаи, а не разность двух summary.
- Ошибка среды: доказательно классифицировать, не менять самостоятельно system services/зависимости.
- Тесты прошли, часть контракта не покрыта: раскрыть ограничение, не обещать отсутствие ошибок.
- Посторонняя задача: не загружать скилл; явный/неявный выбор различаются.
