# Решение Б по нативным проектным триггерам

Принято пользователем 2026-11-24 (Europe/Minsk). Для Codex и Claude Code сохраняется прямой запуск. Синхронные проектные триггеры владеют обеими сверками. Полнота текстов always loaded правил и необходимых SKILL.md проверяется отдельно.

| Состояние | Критерий приёмки |
|---|---|
| Сработавший триггер подтвердил обе сверки | Зафиксировать последовательность, оба результата и допуск до первого предметного действия |
| Сработавший триггер явно отказал при конфликте или требовании нового сеанса | Подтвердить блокировку до передачи промпта модели и отсутствие предметных обращений |
| Триггер пропущен, аварийно завершился, превысил тайм-аут или результат недоступен | Зафиксировать, получил ли промпт модель и что увидел пользователь. Без двух результатов сверка остаётся неподтверждённой. Продолжение клиента учитывается в пределах принятого ограничения |

Раздельно учитывать установку, доверие и фактический запуск по каждому клиенту и режиму. Прежняя изолированная проверка показывает уже наблюдавшиеся ограничения Codex CLI и App Server. Прочитай файл [2026-11-24-codex-hook-admission-probe.md](2026-11-24-codex-hook-admission-probe.md).

## Момент загрузки защищённого входа в Codex

Codex CLI 0.166.0. Изолированный профиль, синтетический проект и локальный тестовый ответчик. Ответчик зафиксировал наличие маркеров A и B в фактическом запросе с предметным промптом и вернул HTTP 400. На время контролей разрешено исполнение только тестовых определений триггеров. Настоящий API, рабочая установка и настройки пользователя не изменялись.

После записи версии B в SessionStart первый запрос содержал версию A. После возобновления с тем же идентификатором запрос содержал оба текста. Только свежий сеанс в этом контроле передал одну версию B. Вложенный Git-каталог и доверенный каталог без Git также вызвали SessionStart и UserPromptSubmit. Вложенный сценарий передал вложенный cwd. Обработчик должен определять корень проекта отдельно от cwd и поддерживать проекты без Git, где клиент обнаружил проектные настройки.

В следующем контроле SessionStart сохранял версию на момент нового сеанса, отмечал восстановленный сеанс как требующий перезапуска и сохранял прежнюю запись при возобновлении. Она не проверяет реальный обработчик сверки файлов или установщик.

## Следующее решение

Прежнее требование разрешало пользователю явно одобрить конкретную задачу с показанными SHA-256 и расхождениями. Явный отказ UserPromptSubmit останавливает исходный промпт до модели. Согласование через следующий обычный промпт того же сеанса будет проходить ту же проверку. Следует решить, передавать ли триггеру отдельное версионное разрешение через INBOX или требовать устранения расхождения и свежего сеанса перед продолжением. Вариант Б по доступности триггера сам по себе этот вопрос не решает.

Реализация, проверка точного Канидата INBOX и U4 открыты. Публикация, переключение рабочей установки и архив требуют отдельных решений.
