# U4. Возврат после явного отказа проектного триггера

Пользователь принял вариант Б 2026-11-24 (Europe/Minsk). После явного отказа при известном расхождении нужны восстановление из опубликованного канона и свежий сеанс. Допуск конкретной задачи по отдельному разрешению продолжить с расходящимися файлами отменён. Существующие отличающиеся файлы сохраняются до разрешённого резервного коммита и восстановления через INBOX. Выбранный порядок совместим с ранее принятым ограничением для пропущенного или аварийно завершившегося триггера. Прочитай файл [2026-11-24-native-hook-admission-decision.md](2026-11-24-native-hook-admission-decision.md).

Проверено в изолированных установках common-only и common+project, Codex CLI 0.166.0. Синхронный тестовый UserPromptSubmit по очереди вызывал оба режима скрипта без записи. При отказе он оставлял отметку по идентификатору сеанса и возвращал код 2. Разрешение в промпте состояние не меняло. Нативное исполнение разрешено только для тестовых определений этих стендов. В запросах к локальному тестовому ответчику проверены все маркеры, включая маркеры прежних ходов. Ответчик вернул HTTP 400. Реальный API не использовался.
