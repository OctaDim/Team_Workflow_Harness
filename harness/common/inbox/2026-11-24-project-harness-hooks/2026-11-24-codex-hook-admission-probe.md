# Проверка допуска через проектные триггеры Codex

Дата — 2026-11-24 (Europe/Minsk). Codex CLI и App Server 0.166.0. Использован отдельный доверенный Git-проект с проектными определениями двух синхронных командных триггеров, чистые профили и локальный тестовый ответчик. Он считал запросы с синтетическим промптом и возвращал HTTP 400. Реальный API, пользовательские настройки и рабочая установка не использовались. Это проверка поведения клиента, обработчик сверки ещё не интегрирован.

В App Server ответ hooks/list под индексом 2 показал обе проектные записи включёнными и не одобренными. Вызов turn/start был принят в событии 6. События hook/started и hook/completed отсутствуют. Локальный ответчик получил промпт, затем turn/completed в событии 14 зафиксировал его HTTP-ошибку. SHA-256 трассы — `5a58a2b135d1e40d8b14a4be943d4540665b91cc09a31d774f5c0b3a23773c47`.

В контрольных прогонах CLI запуск тестовых определений разрешён только для этого запуска специальным параметром CLI. Эти прогоны проверяют обработку результата и тайм-аута. Штатное одобрение через /hooks отдельно не проверялось. Нулевой выход CLI в контроле кода 2 означает прекращение обработки до обращения к модели. Текст причины из stderr обработчика в CLI JSON не появился. В прогоне с неодобренными триггерами CLI JSON не содержал подсказки об открытии /hooks.

Установленные синхронные триггеры могут отклонить промпт. Проектная конфигурация сама по себе не обеспечивает отказ при пропуске исполнения, аварийном завершении или тайм-ауте. В App Server событие turn/start уже разрешило обработку до появления любых событий о триггере. Простая подписка на эти события подходит для доказательства выполнения. Для гарантии требуется механизм, который удерживает передачу промпта до подтверждения обеих сверок. Для Codex Desktop фактическое поведение не проверено. Для Claude Code нативные прогоны не выполнены. Установленная 2.1.260 ниже версии, для которой документация описывает onFailure: block. [OpenAI Docs о доверии к триггерам](https://learn.chatgpt.com/docs/hooks#review-and-trust-hooks) · [OpenAI Docs о событиях App Server](https://learn.chatgpt.com/docs/app-server#turn-events) · [Claude Code о блокировке при ошибке](https://code.claude.com/docs/en/hooks#block-the-action-when-a-hook-fails)

Для следующего решения предлагается проектный способ запуска, который отказывает при отсутствии подтверждения успешного выполнения до передачи промпта. Резервный вариант требует явно принять ограничение прямого запуска клиентов и пересмотреть критерий. Проектные события и проверка полноты контекста остаются отдельными. Право продолжить с известным расхождением из прежней схемы нужно согласовать для нового допуска отдельно. Оно не подтверждает факт выполнения триггера.
