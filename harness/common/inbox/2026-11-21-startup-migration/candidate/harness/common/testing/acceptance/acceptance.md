# Приёмка двух режимов установки harness

Требования согласованы: 2026-10-04. Перенесены: 2026-10-05. Полная приёмка ещё не выполнена.
Объект: [comm-package-independence.md](../../rules/comm-package-independence.md).

| Режим | Условия проверки | Требуемый результат |
|---|---|---|
| Только common | В чистый проект скопирован только common, project отсутствует; исходный проект недоступен | Стартовая проверка создаёт полный нейтральный project из общего описания, без рабочих материалов прежнего проекта |
| Common+project | Перенесены оба пакета, project содержит рабочие материалы | Проверка сохраняет существующий project побайтно и не создаёт вместо него пустой каркас |
| Нарушенная комплектность | В изолированной копии удалён обязательный локальный ресурс или повреждена ссылка | Проверка восстанавливает управляемую рабочую копию из опубликованного канонического файла. При повреждении обязательного канонического источника, конфликте защищённого входа или лишнем always loaded правиле она сообщает причину и останавливается до записи |

Приёмка должна отдельно показать комплектность, подключение к Codex/Claude и поведение. Проверка существования файлов не доказывает чтение агентом, а успешный запуск инструмента не доказывает обязательность его запуска.
Ссылки на источники происхождения опыта не должны становиться скрытыми обязательными зависимостями установленной папки. Возможности и ограничения живого проекта проверяются отдельно от автономной работоспособности пакета знаний; отсутствие приложения в чистом временном проекте нельзя выдавать за успешную проверку его поведения.
Существующие глобальные скиллы автора или соседние каталоги не должны маскировать неполноту тестовой копии.
Формат подключения задан [placement-contract.md](../../skills/comm-publish-harness-instructions/references/placement-contract.md): скиллы устанавливаются полными обычными копиями в .agents/skills и .claude/skills, правила — в .claude/rules; Claude загружает правила нативно, Codex читает их по указанию AGENTS.md. Здесь зафиксированы критерии приёмки выбранной схемы; её выбор не означает завершения нативной проверки. В отчёте указать доступность клиента, модели и наблюдаемую часть сессии.

## Состав проверок, уточнённый 2026-10-05

### Файлы и перенос

Для каждой изменённой рабочей ссылки проверить действие («Прочитай файл» или «Открой каталог») и тип цели. «Запусти» и «Выполни» допускаются для команд и скриптов. В обычном Markdown открыть относительную ссылку от каталога документа, сверить точное имя, регистр и раздел. Если требуется побайтное равенство, сравнить SHA-256 канонического источника и каждой установленной копии. Из каждого расположения проверить один и тот же путь в одинарных обратных кавычках без начального слеша от корня соответствующей установки. В обоих режимах проверить собственный ресурс, ресурс соседнего скилла и переход из checks.md к project-skeleton.json. Разные или недоступные цели предъявить пользователю до продолжения. После изменений проверить весь набор действующих ссылок. Ссылка с необязательным заголовком (title) проверку не проходит. Исторические артефакты исключены из обхода.

Для каждого из двух режимов проверять рабочие локальные Markdown-ссылки, пути к справочным файлам и ресурсам, команды и скрипты, требуемые инструкциями. Отсутствие ресурса, выход обязательной ссылки за границы пакета или скрытая зависимость common от исходного project должны давать ошибку. Пути назначения установки в корне нового проекта отличаются от ссылок на обязательные исходные ресурсы; установка не должна читать соседний или исходный пакет. Внешние URL проверяются отдельно и не служат доказательством локальной комплектности.

Чистые временные копии проверяются без доступа к исходному проекту и его материалам. Новый cwd и пустой HOME сами по себе не обеспечивают изоляцию на уровне ОС. Негативные контроли: повреждённая ссылка, отсутствующий ресурс, различающиеся зеркала, игнорируемый общий материал, неожиданная зависимость от глобального авторского скилла.

### Реальное обнаружение и применение

В каждом режиме запустить отдельно Codex и Claude Code в чистом окружении с установленными нативными копиями. Проверить уникальный тестовый скилл: наличие в списке, явный вызов и контрольное действие с использованием ресурса из его собственной папки. Автоматический выбор по description проверять отдельно; результат зависит от задачи и не заменяет явный вызов. Для правил отдельно проверяется загрузка обязательного ограничения до выбора процедуры и отсутствие обхода через индивидуальный материал.

Для каждого режима и агента сохранить версию, команду или способ запуска, наблюдаемый результат и ограничения. Невозможность запуска означает «не проверено». Совпадение файлов, validator или generic Plugin Eval не означают обнаружения нативным приложением. Установленные authoring skills и глобальные конфигурации не должны скрывать недостающие ресурсы.

Статусы скилла или правила фиксировать отдельно: «Codex — проверено/не проверено»,
«Claude — проверено/не проверено», с результатами каждого обязательного режима.
Полная проверка требует «проверено» у обоих для одной итоговой компактной версии
и успешных общих проверок. Без неё перенос в канонические и нативные папки —
только с явным разрешением и подтверждением пользователя; статусы не повышаются
из-за разрешения. [SKILL.md](../../skills/comm-validate-harness-instructions/SKILL.md);
[gate.md](../../skills/comm-publish-harness-instructions/references/gate.md).

### Начальный контекст

В штатных прогонах `AGENTS.md` и `CLAUDE.md` соответствуют каноническим шаблонам. `AGENTS.md` содержит указание прочитать always loaded правила из `.claude/rules`. Отдельно от штатных прогонов проверь отсутствие и расхождение обоих защищённых входов и комбинированные расхождения always loaded правил. Пустой `AGENTS.md` отличается от канона, нулевой `CLAUDE.md` ему соответствует. Создание входов из шаблонов при чистом переносе относится к проверке установки.

Отдельно измерить два режима: начальные обязательные указатели и ограничения, а также нативный каталог названий/описаний скиллов. Объём всех файлов пакета не является стартовым контекстом. Инструкции установки, подробности процедур и тела README.human.md не должны попадать в стартовую загрузку. Бюджеты always loaded правил и контекстных lazy скиллов оцениваются по отдельности. Способ подключения задан [placement-contract.md](../../skills/comm-publish-harness-instructions/references/placement-contract.md); результаты его проверки и статусы Codex и Claude учитываются отдельно.

## Проектный каркас и исключённый режим

В первом режиме проверить все согласованные категории, нейтральную карту INDEX и отсутствие рабочего START, наличие человеческих пояснений и повторный запуск без изменений. Во втором сохранить байты существующих проектных материалов и отдельно проверить, что новая редакция общего шаблона не дополняет проект автоматически. Проектные подпапки, например docs/epl-import/, не экспортируются в шаблон.

Изменение состава — через отдельную common inbox-заявку, отдельное явное решение и отдельное явное подтверждение пользователя; предложение или отсутствие ответа не разрешают добавление. Состав текущего каркаса согласован отдельно; новые проекты без lessons, plans в docs/plans. Existing legacy lessons сохраняются обычным стартом.

Отсутствие common даёт отказ: project-only является неподдерживаемым состоянием, не третьим режимом установки. Синхронный UserPromptSubmit дожидается одного вызова [ensure_entrypoint_links.py](../../checks/ensure_entrypoint_links.py) для сравнения SHA-256 обоих защищённых входов и always loaded правил. Успешный вывод — только `OK`. При смешанном расхождении сверить список путей и их состояний. Подтвердить отсутствие записи во время сверки и при совпадении, включая пару пустых файлов.

В обоих режимах подтвердить запуск проектного триггера Codex из корня и вложенного каталога. Для Claude Code подтвердить обычный запуск из корня и запуск из вложенного каталога с `--settings`, указав абсолютный путь к корневому `.claude/settings.json`. Запуск Claude Code из вложенного каталога без этого параметра учитывать как диагностический контроль с неподтверждённой сверкой.

Отдельно подтвердить автоматическое восстановление отсутствующей копии и пустого отличающегося защищённого входа. Перед заменой непустого входа или изменённого always loaded правила сверить резервный коммит. Проверить полный Git ID, список и SHA-256 сохранённых файлов, отказ при ошибке резервного коммита и автоматическое удаление лишнего файла только после проверки его резервной копии. После восстановления повторить сверку, проверить блокировку прежнего сеанса и допуск свежего. Результаты записать раздельно для Codex и Claude Code по обоим режимам.

Исторические свидетельства трёх независимых режимов сохраняются как история и не подменяют текущую приёмку. Новые результаты, hashes и реальные ограничения фиксируются отдельно.

Указатели на текущих владельцев обновлены 2026-10-08; даты и исторические
результаты выше не изменены этим переносом.

## Полнота текста и момент применения

Граница проверки — момент запроса действия по задаче, включая поиск её файлов. Если вызов запрашивает и стартовые тексты, и действие по задаче, его выдача приходит слишком поздно для этого действия. До запроса сверить для каждого пути полноту байтов и версию. Один результат инструмента может содержать несколько или все always loaded правила. Проверить такой старт без отдельного перечисления, а также объединение нативной и явной загрузки. При потере конца одного файла остальные полные файлы засчитываются. Проверить дочитывание именно этой версии и повторное использование уже полного текста. Невидимую доставку отметить как ограничение наблюдения.

| Испытание | Наблюдаемый результат |
|---|---|
| Безусловная ссылка | Сразу после выдачи с содержащим ссылку always loaded правилом получен полный SKILL.md до любой задачи, либо его полный актуальный текст уже доступен. |
| Условие выполнено при постановке задачи | При запросе изменить конфигурацию полный SKILL.md получен до первой правки. При запросе только объяснить значение достаточно метаданных. |
| Условие впервые наступает в середине задачи | Объяснение выполнено без преждевременного чтения. После возникновения необходимости правки агент получает полный SKILL.md до первой правки. |
| Обрезанная или недоступная выдача | Агент дочитывает ту же версию. При невозможности останавливается, называет пути и причину и ждёт решения. До получения обязательного текста зависимое действие отсутствует. |
| Преждевременное действие | При установленном пропуске любого always loaded правила до первого действия фиксируется критическая ошибка с путём и причиной, даже если текст прочитан позднее. |

Проверить ссылки по текстовому имени скилла и по пути к SKILL.md, каждую ссылку смешанного набора, повторное обращение к одному файлу и независимый нативный выбор по name и description. Различать метаданные, полный текст и наблюдаемое применение.

## Сравнение карт INDEX

Сопоставить обязательное чтение обеих карт с чтением по необходимости в одинаковых свежих установках для каждого клиента и каждого режима. Сохранить задачу, редакцию файлов, порядок и число повторов, правильность выбора, прочитанные пути и расход входных токенов до первой содержательной операции либо ответа. Отдельно указать учёт кэша и доступную точность счётчика. Для контроля использовать задачу без контекстного lazy скилла и поиск действующего требования при похожем историческом отчёте. Для принятого режима проверить в обеих установках задачу без карт и навигацию по каждому пакету отдельно: содержательный ответ получен, открыта нужная карта, вторая открывается только при собственной необходимости. Для задачи по обоим пакетам доступны обе карты.

## Источник восстановления и публикация

Восстановить удалённую рабочую копию, пока версия 2 ещё в INBOX, и сравнить с канонической версией 1. Опубликовать конкретную версию 2 после разрешения в тестовой заявке, удалить тестовую заявку и повторить восстановление. При прерывании между фазами проверить остановку старта, сохранность третьей версии и возобновление того же набора. При полном успехе в файловых сценариях отдельно указать, какую часть поведения удалось подтвердить по каждому нативному клиенту.
