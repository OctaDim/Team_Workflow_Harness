# Verify current project facts

Identify the claim, decision, project version, environment and authorized evidence.

1. Check applicable current code, configuration, research, decisions, requests and connected sources. Separate observations, contracts and hypotheses. Verify dated claims against current authoritative evidence.
2. For absence check naming, coverage, filters and positive controls. Incomplete searches leave the claim unresolved. For an empty log search, including one reported secondhand, read `harness/common/skills/comm-verify-project-facts/references/empty-log-results.md`.
3. Verify availability directly within permissions. Catalog or health alone is insufficient. Report missing evidence or access.
4. For Git, read the resource matching the claim.
   - Revision freshness: `harness/common/skills/comm-verify-project-facts/references/git-base-state.md`.
   - Integration, supersession, continued presence, deployment or frozen comparisons: `harness/common/skills/comm-verify-project-facts/references/git-integration.md`.
   - Effects of attempted changes, including PR fields: `harness/common/skills/comm-verify-project-facts/references/git-operation-result.md`.
5. Report sources, version, date, observations, contradictions, limits, conclusions and affected statements. Follow the evidence and recording routes. Preserve history. Obtain separate authority for solution choice, repair or mutation.
