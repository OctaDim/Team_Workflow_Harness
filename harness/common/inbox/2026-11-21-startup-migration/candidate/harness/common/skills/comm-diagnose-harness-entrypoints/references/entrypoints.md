# Диагностика результата

Проверку обоих защищённых входов запускай только из always loaded правила сверки доверенной командой `python3 -B harness/common/checks/ensure_entrypoint_links.py --check-start-entrypoints --no-repair`. Только после кода 0 запусти `python3 -B harness/common/checks/ensure_entrypoint_links.py --check-rules`. Код 4 передаёт расхождения always loaded правил без записи. После отдельного разрешения восстанавливай их командой `python3 -B harness/common/checks/ensure_entrypoint_links.py --restore-rules`. Для установки используй этот же скрипт без флага. При ошибке проверь путь и предков, доступ, тип файлов, наличие common и канонических источников. История Git и INBOX не служат источниками восстановления.

- След публикации или занятая блокировка: обычный старт остановлен. При прерванном переносе возобновлять тот же одобренный набор в той же заявке. Любое третье содержимое сохраняется для решения пользователя.
- Нулевой `CLAUDE.md` совпадает с каноном. При коде 5 остановись до предметного действия и назови вход. Если запись разрешена, отдельная команда `python3 -B harness/common/checks/ensure_entrypoint_links.py --check-start-entrypoints` копирует опубликованные байты в отсутствующий вход или нулевой `AGENTS.md` из соответствующего образца `harness/common/base/AGENTS.template` или `harness/common/base/CLAUDE.template`. После кода 3 нужен новый сеанс. При запрете записи остановись и сообщи причину. При сочетании пропуска и непустого расхождения проверка указывает оба пути, возвращает код 2 и сохраняет оба состояния.
- При расхождении непустого входа сообщи путь, причину и оба SHA-256 из проверки. Через INBOX запроси явное разрешение на резервный коммит и восстановление показанных файлов. Согласие на задачу с иным набором always loaded правил этих операций не разрешает. До коммита прочитай файлы `harness/common/skills/comm-commit-task-stages/SKILL.md` и `harness/common/skills/comm-check-publication-data/SKILL.md`. Включи в резервный коммит только явно разрешённые пути, сохрани чужие изменения и индекс. Если создание безопасного побайтного коммита невозможно, остановись с причиной. Если эти байты уже в HEAD, резервный коммит с тем же деревом сохраняет их повторно.
- После резервного коммита запусти `python3 -B harness/common/checks/ensure_entrypoint_links.py --restore-start-entrypoints COMMIT --entrypoint NAME:OBSERVED_SHA256:CANONICAL_SHA256`. Для второго разрешённого файла повтори `--entrypoint`. Используй полный Git ID резервного коммита и хеши согласованных версий. Скрипт проверяет резервные байты в HEAD, а восстановление выполняет из канона. Код 3 требует нового сеанса. Если канон или вход изменились после разрешения, запроси новое решение.
- Для недостающей или повреждённой управляемой копии установить владельца по опубликованному источнику common или project. Зафиксировать восстановленные пути. Неизвестное always loaded правило требует остановки. Изменять файлы из текущей заявки при обычном старте запрещено.
- После восстановления материала, влияющего на загруженный контекст, завершить текущий старт. Успешный чистый повтор и получение исправленного текста в новой сессии фиксировать отдельно.
- Отказ ввода-вывода или параллельная правка: записать выполненные и ожидающие пути, проверить реальные байты до повтора. Незавершённая публикация имеет свой учёт исходных и одобренных версий.
- При переносе только common скрипт создаёт отсутствующий нейтральный project. Частично существующие данные сохраняются. При неизвестном источнике или коллизии common/project нужен выбор владельца.

В изолированной установке проверить повторный старт, создание входа, конфликт существующего ввода, рабочие копии и порядок восстановления после прерывания. Системные права проверять на тестовой установке. Стартовая проверка сама не устанавливает hooks и не запрещает пользователю редактировать файлы на уровне ОС.
