# Владение материалами и разрешения

До выбора процедуры соблюдай comm-/proj- требования; личный скилл не разрешает обход. Конфликт common/project согласуй до зависимого действия.

До записи классифицируй назначение и операцию. Разрешённые создание/обновление идей, исследований, решений, спецификаций, планов, handoff и результатов приложения — прямо в постоянные категории project с фактическими статусами. Перенос/очистку согласуй отдельно. Механизм project (структура, поведение, процедуры, исполняемые проверки, настройки) — project/inbox; весь common, включая память/результаты, — common/inbox. Проверяй содержимое родительской операции; смешанное защищено, неясное уточняй.

Перед защищённой правкой, записью/обработкой заявки или защищённой памяти прочитай файл `harness/common/skills/comm-process-harness-inbox/SKILL.md`. Штатные создание/восстановление стартовой проверкой исключены. Стадии INBOX согласуй явно: создание, выполнение, публикацию. Обрабатывай последовательно по старшинству до закрытия. Согласованное не переспрашивай. Прямая правка требует явного поручения изменить указанный материал напрямую и отдельного однозначного согласия после вопроса агента о конкретной правке. Проверь диалог; иначе спроси/жди. Предварительное согласие, вызов скилла, молчание/неоднозначность недостаточны. Защищённые входы — только через INBOX.

Перед записью evidence, включая work/, прочитай файл `harness/common/skills/comm-protect-harness-evidence/SKILL.md`. Прямые операции с любыми common evidence и свидетельствами механизма project, включая перенос/удаление/родительские операции, запрещены без согласованного исключения. Старые свидетельства сохраняй по исходным путям. Исходные логи/снимки неизменяемы; завершённый отчёт исправляй новым датированным связанным дополнением.

Перед сохранением опыта/размещением прочитай файл `harness/common/skills/comm-preserve-harness-knowledge/SKILL.md`. Для механизма установи поведение/владельца; исключи дублирование. Отделяй решения приложения от поведения агента. До проектирования/изменения контекстного lazy скилла или always loaded правила прочитай файл `harness/common/skills/comm-create-lazy-claude-codex-skills/SKILL.md`. Предпочитай контекстный lazy скилл; постоянное чтение требует основания.

Оценивая always loaded правило, контекстный lazy скилл или Канидат INBOX, прочитай файл `harness/common/skills/comm-validate-harness-instructions/SKILL.md`; для разрешённой публикации/восстановления вне автоматического старта прочитай файл `harness/common/skills/comm-publish-harness-instructions/SKILL.md`. Привяжи отчёт/явное разрешение к точным путям/хешам набора. Проверь обоих клиентов в обоих режимах; правка сбрасывает статусы. Пропуски обоснуй; дождись явного разрешения именно этой неполной версии. Выявленное расхождение исправь. Восстанавливай копии из опубликованных канонических файлов.

Если блокировка требует нового решения (включая auto-review), до ответа прочитай файл `harness/common/skills/comm-resolve-permission-blockers/SKILL.md`. Объясни действие/причину/источник/получателя, спроси/жди без обхода. Отказ соблюдай; новую блокировку согласуй; однозначную техническую ошибку исправь в разрешённых пределах.
