# Спецификация миграции старта

Редакция для согласования, 2026-11-21. Основание — [request.md](request.md). Здесь определены наблюдаемые результаты. Состояние выполнения учитывается в заявке. Статусы проверки будущей версии по обоим клиентам пока «не проверено».

## Объём исходной инвентаризации U1

Числа и коды ниже относятся к первоначальной инвентаризации. Актуальная область U3 и V6 охватывает только рабочий harness и установленные копии. Исторические артефакты исключены из проверки и исправления ссылок.

Исходная точка Git — `6860b4c6ae55215a616400bac21dedc93dac02eb`. Учитывались фактические файлы рабочего дерева, включая незакоммиченные версии. Обход охватил Markdown в `harness/`, обеих установках скиллов, `.claude/rules/`, двух корневых входах и `docs/` для поиска обратных ссылок на старт. Каталог этой заявки исключён во избежание самоссылок отчёта. Код и шаблоны стартового механизма осмотрены отдельно. В `.codex/` Markdown не обнаружен. Человеческие пояснения обработаны программно. Их тела в контекст не выводились.

[inventory.tsv](inventory.tsv) содержит путь, владельца, вид операции, номера проверок, счётчики ссылок, маркер упоминания прежнего старта и SHA-256 **содержимого исходного файла**. Коды операций:

| Код | Предлагаемая операция |
|---|---|
| E / S / I | E — изменить протокол входов, образец или генератор. S — снять рабочий START после сохранения копии и переноса обязанностей. I — оставить карту и сравнить способы её чтения. |
| R / K / W | R — проверить обязанности канонического always loaded правила. K — проверить владеющий скилл и его ресурсы. W — синхронизировать управляемую копию из указанного канонического пути при изменении источника. |
| T / C | T — изменить устаревшее ожидание проверки или сохранить его как регрессионный контроль. C — проверить совместимость существующего описания категорий. |
| H / D | H — установить назначение исторического документа, текущей заявки или свидетельства до изменения. D — сверить цель документации, актуальность содержания и ссылки с владельцем материала. |

[link-review.tsv](link-review.tsv) содержит 527 переходов, отобранных из-за отсутствия цели, имени `START.md` или фрагмента. Для каждого сохранены текущий источник, начальная строка блока, разобранный адрес, вычисленная цель и фрагмент. Одна строка может удовлетворять нескольким признакам. Метод — разбор ссылок, ссылок по определениям и изображений CommonMark с таблицами. Литералы в примерах и коде учитываются отдельно как упоминания. Простая проверка пути не устанавливает доступность раздела, работоспособность в интерфейсе клиента или исходную версию на дату создания. При реализации отдельно разобрать HTML, неиспользованные определения, специальные конструкции рендерера и пути в генераторах. Новые материалы этой заявки также проверить перед публикацией. TSV — инвентаризация исходного состояния, итоговый отчёт составляется после переходов в обеих версиях.

## Контракт приёмки

| Проверка | Начальное состояние и действие | Наблюдаемый результат |
|---|---|---|
| V1. Старт и каркас | Чистая установка только common, установка с заполненным project, повторный старт, отказ project-only. Создать недостающие входы. Отдельно открыть установки с посторонним always loaded правилом и с существующим расходящимся входом. | Нейтральный project создаётся только при отсутствии. Повторный старт сохраняет байты. Два действующих START отсутствуют. Созданы точные входы. При конфликте получены путь и причина до задачи, существующий текст сохранён. Пути и их предки проверены на симлинки. |
| V2. Восстановление | Опубликована версия 1, версия 2 готовится в INBOX. Удалить или повредить управляемую копию в изолированной установке. Затем опубликовать версию 2 в стенде и повторить восстановление после удаления закрытой тестовой заявки. | В обоих случаях восстанавливаются байты соответствующей **опубликованной** версии. Вложенные кандидаты, исторические снимки и Git не участвуют в выборе источника. Прямой путь INBOX → рабочая копия исключён. |
| V3. Согласованный набор | Снять или выдать разрешение на точные версии, подменить файл после отчёта, прервать публикацию после записи каждого типа файла, имитировать параллельную правку. | Изменённая версия требует нового одобрения. Во время неполного перехода старт останавливается. Повторное выполнение сверяет старые/новые хеши, сохраняет стороннюю правку, завершает тот же набор. Исправленные входы и ранее загруженные устаревшие тексты проверяются в свежей сессии. |
| V4. Получение и применение | Для каждого клиента и режима проверить безусловные, условные, смешанные и повторные ссылки. Полный, частичный и ошибочный вывод. Выбор по описанию и по ссылке. Объяснение конфигурации, затем правка. | До задачи покрыты все ожидаемые always loaded правила и обязательные в этот момент `SKILL.md`. Позже агент получает нужный текст до первого зависимого действия. Полное получение подтверждает наблюдаемая выдача той же версии. При уже полном тексте повторное чтение избыточно. При невозможности дочитать агент останавливается и ждёт решения. Фиксируются источник загрузки и отдельно действие. |
| V5. INDEX | В двух вариантах установок совпадают тексты ограничений, карта, задача и нативный каталог. Изменяется только обязательность чтения карт. Прогоны для обоих клиентов и обоих режимов. | Для каждого сценария сопоставлены выбранный скилл, открытые пути, случаи пропуска/повтора, ход поиска и входные токены до одной отсечки. Отдельные результаты по клиентам представлены пользователю до решения по INDEX. |
| V6. Рабочие ссылки | Найти нерабочие переходы в действующих файлах harness и установленных копиях до и после переключения. Каждая изменённая рабочая Markdown-ссылка кликабельна и отсчитывается от каталога файла, с точным именем цели в подписи. Для канонической и каждой установленной копии независимо сверить путь, владельца, содержимое и указанный раздел. Расхождение целей или недоступность требуют явного решения пользователя. | Исправление указывает действующего владельца или учитывает снятый этап. В отчёт входят изменения рабочих ссылок. Исторические артефакты исключены из проверки и исправления ссылок. |
| V7. Снимок, временный архив, отчёт | Сверить сохранённый в `history/harness/` снимок действующих файлов обоих пакетов и текущей заявки по составу и байтам. Прочие заявки, исторические отчёты и другие артефакты исключены. Для временного архива отдельно проверить распаковку и доступность коммита в удалённой ветке перед удалением после приёмки. | Сохраняются снимок каталога и отчёт о рабочих ссылках. Статус заявки отражает фактически выполненные операции. |

Для V1–V5 отличать структурную проверку, регистрацию, наблюдаемое получение текста и поведение в новой сессии. При возможности наблюдать только явное чтение это указывается в отчёте. Сводка содержит клиент, режим, сценарий, ожидание, факт, пропуски и их причины. При неполной проверке действуют оговорённые в заявке условия явного разрешения для конкретной версии.
