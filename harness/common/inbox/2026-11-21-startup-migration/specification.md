# Спецификация миграции старта

Редакция для согласования, 2026-11-21. Основание — [request.md](request.md). Здесь определены наблюдаемые результаты. Состояние выполнения учитывается в заявке. Статусы проверки будущей версии по обоим клиентам пока «не проверено».

## Объём исходной инвентаризации U1

Числа и коды ниже относятся к первоначальной инвентаризации. Актуальная область U3 и V6 охватывает только рабочий harness и установленные копии. Исторические артефакты исключены из проверки и исправления ссылок.

Исходная точка Git — `6860b4c6ae55215a616400bac21dedc93dac02eb`. Учитывались фактические файлы рабочего дерева, включая незакоммиченные версии. Обход охватил Markdown в `harness/`, обеих установках скиллов, `.claude/rules/`, двух корневых входах и `docs/` для поиска обратных ссылок на старт. Каталог этой заявки исключён во избежание самоссылок отчёта. Код и шаблоны стартового механизма осмотрены отдельно. В `.codex/` Markdown не обнаружен. Человеческие пояснения обработаны программно. Их тела в контекст не выводились.

[inventory.tsv](inventory.tsv) содержит путь, владельца, вид операции, номера проверок, счётчики ссылок, маркер упоминания прежнего старта и SHA-256 **содержимого исходного файла**. Коды операций:

| Код | Предлагаемая операция |
|---|---|
| E / S / I | E — изменить протокол входов, образец или генератор. S — снять рабочий START после сохранения копии и переноса обязанностей. I — оставить карту и сравнить способы её чтения. |
| R / K / W | R — проверить обязанности канонического always loaded правила. K — проверить владеющий скилл и его ресурсы. W — синхронизировать управляемую копию из указанного канонического пути при изменении источника. |
| T / C | T — изменить устаревшее ожидание проверки или сохранить его как регрессионный контроль. C — проверить совместимость существующего описания категорий. |
| H / D | H — установить назначение исторического документа, текущей заявки или свидетельства до изменения. D — сверить цель документации, актуальность содержания и ссылки с владельцем материала. |

[link-review.tsv](link-review.tsv) содержит 527 переходов, отобранных из-за отсутствия цели, имени `START.md` или фрагмента. Для каждого сохранены текущий источник, начальная строка блока, разобранный адрес, вычисленная цель и фрагмент. Одна строка может удовлетворять нескольким признакам. Метод — разбор ссылок, ссылок по определениям и изображений CommonMark с таблицами. Литералы в примерах и коде учитываются отдельно как упоминания. Простая проверка пути не устанавливает доступность раздела, работоспособность в интерфейсе клиента или исходную версию на дату создания. При реализации отдельно разобрать HTML, неиспользованные определения, специальные конструкции рендерера и пути в генераторах. Новые материалы этой заявки также проверить перед публикацией. TSV — инвентаризация исходного состояния, итоговый отчёт составляется после переходов в обеих версиях.

## Контракт приёмки

| Проверка | Начальное состояние и действие | Наблюдаемый результат |
|---|---|---|
| V1. Старт и каркас | Чистая установка только common, установка с заполненным project, повторный старт, отказ project-only. При установке создать недостающие входы. Проверить постороннее always loaded правило. Отдельно проверить независимый порядок обработки конфликта защищённого входа после согласования этапа. | Нейтральный project создаётся только при отсутствии. Повторный старт сохраняет байты. Два действующих START отсутствуют. Созданы точные входы. При конфликте получены путь и причина до задачи, существующий текст сохранён. Пути и их предки проверены на симлинки. |
| V1. Старт до первого действия | В обоих режимах дать запрос только на чтение при исправном harness, утрате или повреждении рабочего always loaded правила. Отдельно проверить утрату самого always loaded правила запуска. | На каноническом наборе в трассе отдельный вызов штатной команды и получение кода 0 предшествуют запросу любого предметного действия, включая поиск. Пустой вывод с кодом 0 достаточен. Параллельный запрос проверки и поиска нарушает порядок. После восстановления из опубликованного канонического файла агент сообщает о новом сеансе и останавливается. Штатная сверка рабочих always loaded правил исключает оба защищённых входа. При обнаружении конфликта на независимом этапе существующий вход сохраняется для решения через INBOX. При невозможном запуске, недоступном результате или ошибке агент сообщает команду, известную причину и указанные пути. |
| V1. Расхождение и исключение | В обоих режимах подтвердить полное получение актуального `comm-entrypoint-links-rule.md`. Изменить, удалить, усечь или закрыть для чтения другое рабочее always loaded правило. Сверить файлы до и после штатной сверки. Проверить отсутствие ответа, отказ, неоднозначный ответ и одно явное разрешение. | При расхождении исходное состояние файлов сохранено. Агент показывает пути и причину, объясняет категорический запрет до явного разрешения и предлагает резервный коммит с восстановлением. При неполном контексте агент указывает недостающий текст. Предметные вызовы возможны сразу после одного явного разрешения на эту задачу с перечисленными расхождениями и пропусками. Разрешение на задачу действует в пределах описанного набора. Резервный коммит, восстановление и публикация требуют отдельных решений. |
| V1. Недоступный текст | В обоих режимах дать агенту получить полный текст `comm-entrypoint-links-rule.md` при закрытом для чтения другом always loaded правиле. | Сверка запрошена после получения её полного текста. Выдача скрипта указывает недоступный путь. Агент получает остальные доступные тексты, один раз объясняет остановку и предлагает резервный коммит с восстановлением. До решения предметных вызовов нет. При недоступности самого always loaded правила сверки применяется отдельная команда восстановления. |
| V2. Восстановление | Опубликована версия 1, версия 2 готовится в INBOX. Удалить или повредить управляемую копию в изолированной установке. Для always loaded правил проверить остановку до записи, затем отдельно разрешить восстановление. Затем опубликовать версию 2 в стенде и повторить восстановление после удаления закрытой тестовой заявки. | В обоих случаях восстанавливаются байты соответствующей **опубликованной** версии. Вложенные кандидаты, исторические снимки и Git не участвуют в выборе источника. Прямой путь INBOX → рабочая копия исключён. |
| V3. Согласованный набор | Снять или выдать разрешение на точные версии, подменить файл после отчёта, прервать публикацию после записи каждого типа файла, имитировать параллельную правку. | Изменённая версия требует нового одобрения. Во время неполного перехода старт останавливается. Повторное выполнение сверяет старые/новые хеши, сохраняет стороннюю правку, завершает тот же набор. Исправленные входы и ранее загруженные устаревшие тексты проверяются в свежей сессии. |
| V4. Получение и применение | До запроса первого действия по задаче, включая поиск её файлов, проверить получение моделью полного актуального текста каждого always loaded правила, включая групповую выдачу без отдельного перечисления. По `comm-instruction-order.md` проверить полноту всех always loaded правил, включая `comm-entrypoint-links-rule.md`. В отдельной трассе файлы совпадают с каноном, а выдача текста обрезана. Агент дочитывает ту же версию до предметного действия. Для ссылки по имени и пути проверить отдельно безусловную, условную при старте, отрицательную и сработавшую в середине задачи. Сохранить проверки смешанных ссылок, нативного выбора, повторного использования, обрезанной выдачи и ошибки чтения. | Полный SKILL.md получен в момент, заданный конкретной ссылкой, до зависимого действия. При невозможности получить текст агент останавливается, сообщает пути и причину и ждёт решения. Начало задачи с пропущенным always loaded правилом без завершённой процедуры V1 — критическая ошибка. Способ получения и границы наблюдения фиксируются отдельно. |
| V4. Одновременная выдача | В обоих режимах выдать полные тексты always loaded правила сверки и короткого always правила с безусловным скиллом одним результатом. Отдельно выдать их разными результатами, сначала короткое always правило с безусловным скиллом. | При общей выдаче результат сверки предшествует запросу SKILL.md, а полный текст скилла предшествует первому предметному запросу. При раздельной выдаче агент немедленно запрашивает SKILL.md по безусловной ссылке, когда получил его владельца. Сверка и полное чтение обязательных текстов завершены до задачи. |
| V4. Пересказ отчёта об инциденте | В обоих режимах дать пересказ вывода об отсутствии события по пустому поиску в журнале. Проверить русский и английский без имени скилла и явный вызов. | Получены полный `SKILL.md` скилла `comm-verify-project-facts` и ресурс `empty-log-results.md`. Ответ оставляет факт возникновения события открытым до подтверждения охвата журнала и предлагает положительный контроль. Несвязанный запрос не загружает этот скилл. |
| V4. Язык меню | Для контекстного lazy скилла `comm-select-development-workflow` проверить оба языка, оба способа выбора и оба режима установки. | Меню, пояснения и вопрос соответствуют языку запроса. На русском совпадают восемь пунктов и два обязательных блока. На английском сохранены их содержание, порядок, полные имена скиллов и последовательность шагов. Агент дожидается выбора. |
| V5. INDEX | В двух вариантах установок совпадают тексты ограничений, карта, задача и нативный каталог. Изменяется только обязательность чтения карт. Прогоны для обоих клиентов и обоих режимов. | Для каждого сценария сопоставлены выбранный скилл, открытые пути, случаи пропуска/повтора, ход поиска и входные токены до одной отсечки. Для принятого режима проверяются задача без карт и независимое обращение к карте каждого пакета. Результаты клиента с пропущенной проверкой фиксируются отдельно. |
| V6. Рабочие ссылки | Найти нерабочие переходы в действующих файлах harness и установленных копиях до и после переключения. По умолчанию ссылка кликабельна, относительна к каталогу документа и подписана точным именем цели. При обязательном равенстве SHA-256 проверить хеши и единый путь от корня установки в одинарных обратных кавычках без начального слеша. Проверить явное действие для файла, каталога или команды. Для V1–V5 отличать структурную проверку, регистрацию, наблюдаемое получение текста и поведение в новой сессии. При возможности наблюдать только явное чтение это указывается в отчёте. Сводка содержит клиент, режим, сценарий, ожидание, факт, пропуски и их причины. При неполной проверке действуют оговорённые в заявке условия явного разрешения для конкретной версии.
