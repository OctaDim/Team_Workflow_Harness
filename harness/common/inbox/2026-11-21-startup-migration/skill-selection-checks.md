# Нативная проверка 25 контекстных lazy скиллов в Codex

Проверен Канидат INBOX в редакции `6621e62` на Codex CLI 0.166.0. Перечень 25 владельцев получен из канонических операций в реестре публикации. SHA-256 подготовленных канонических файлов и рабочих копий сверены с реестром в обеих чистых установках. Полные папки контекстных lazy скиллов, включая ресурсы, сверены с обеими установками клиентов.

| Режим | По задаче без имени | Явный вызов по имени | Отрицательный контроль |
|---|---:|---:|---|
| common-only | 24/25 | 25/25 | 180 минут, ни одного полного SKILL.md |
| common-project | 24/25 | 24/25 | 180 минут, ни одного полного SKILL.md |

Числители учитывают выбор ожидаемого владельца, полный текст и предметный результат сценария. Стартовая проверка учтена отдельно. В 100 из 100 основных сеансов трасса подтверждает получение полного актуального SKILL.md ожидаемого владельца. В 97 из 100 предметный результат соответствует сценарию. В двух отдельных локальных запусках клиент показал имена и полные описания всех 36 установленных контекстных lazy скиллов. При старте полных SKILL.md было ноль.

## Границы наблюдения

Каждый основной сценарий выполнялся в двух новых сеансах на каждом режиме установки. В первом запрос описывал задачу без имени владельца. Во втором имя было указано явно. Проверялись решения на данных сценария, включая остановку перед операцией без разрешения. Production, Git, браузер, база данных и копии harness за пределами стенда в этих задачах не изменялись. Трасса показывает получение текста и ответ. Для владельцев с применимой ссылкой в always loaded правиле она не позволяет однозначно отделить влияние этой ссылки от нативного описания.

Для каждого сеанса учтены полные тексты по реальной выдаче модели, прочитанные ресурсы, контрольная сумма ответа и выдержка из него. Для меню проверены восемь пунктов и два обязательных блока по версии ресурса. Индексы событий относятся к локальной трассе этого сеанса. Два отрицательных сценария и четыре диагностических повтора учитываются отдельно. Для запросов, ожидаемых действий, пофайловых SHA-256 и отдельных результатов прочитай файл [skill-selection-checks.json](skill-selection-checks.json).

## Расхождения

- В англоязычных сеансах для `comm-select-development-workflow` Codex получил SKILL.md и ресурс меню. Ниже указан результат дословной сверки. Английский запрос просил ответить на английском, а ресурс требует дословной русской редакции. Дополнительный запрос на русском проверял то же меню без этого пересечения требований. Эти прогоны учитываются отдельно от основных.
- После получения всех always loaded правил агент должен запустить штатную стартовую проверку. В 53 из 100 основных сеансов выдача с подтверждением штатного старта поступила до первого распознанного обращения по задаче. В 34 подтверждение получено в общей или более поздней выдаче, включая случаи предварительной проверки пути. В 13 сеансах подтверждение успешного запуска отсутствует. При сравнении с запросом именно целевого SKILL.md успешный старт подтверждён до запроса в 75 случаях. В семи случаях выдачи совмещены или пересекались, в пяти полный SKILL.md уже поступил до подтверждения старта. Во всех 100 сеансах до распознанного запроса по задаче проверены полные тексты 12 always loaded правил. Содержательный ответ в таких сеансах не подтверждает полный старт.
- В контрольном примере `comm-commit-task-stages` в комбинированной установке Codex прямо сообщил, что пропустил штатный запуск, поскольку скрипт может записывать файлы. Задачи основной серии ограничивали предметную работу чтением. В двух дополнительных сеансах того же примера запрос явно разрешал штатную стартовую проверку, и оба запуска завершились до чтения владельца. Этот результат не устанавливает причину остальных пропусков.
