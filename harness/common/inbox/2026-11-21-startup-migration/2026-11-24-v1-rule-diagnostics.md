# U4. Диагностика V1 для рабочих always loaded правил

Дата — 2026-11-24 (Europe/Minsk). Пользователь выбрал вариант А. Уточнено существующее always loaded правило `comm-entrypoint-links-rule.md`, которое уже владеет этой проверкой. Единое предупреждение содержит остановку с путями и причинами, границы резервного коммита и отдельную команду восстановления. Контекстный lazy скилл не нужен для этой ветки допуска, поскольку предупреждение предшествует выбору скиллов. Отдельный скилл с уже краткой диагностикой добавил бы переход на критическом пути.

Для отсутствующей копии сообщил, что сохранять нечего, для недоступной предложил получить доступ на чтение для резервного коммита, для читаемой отличающейся предложил резервный коммит. После утраты самого always loaded правила сверки Codex получил его полный текст из канона, назвал отсутствующий рабочий путь и тоже сохранил остановку. В обоих обычных смешанных прогонах до предметного действия не дошло. В `common-only` полный текст сверки получен событием 39, обе команды пропущены. В обоих случаях до проверки код 4 не получен, поэтому итоговая диагностика всей группы расхождений отсутствует.

## Файловая проверка

- По 206 автоматических тестов в каждом режиме, код 0. Использован штатный `run_tests.py` и pytest 8.4.2.
- В каждом режиме охвачено 504 рабочих документа, 96 внутренних Markdown-ссылок, 359 путей в побайтных копиях и одна внешняя ссылка. Локальная проверка сверила структуру внешней ссылки.
- Отдельное восстановление отсутствующей копии в каждом режиме дало 4 → 3 → 0. Сохранность до команды подтверждена. После кода 3 рабочие байты совпали с каноном, команда потребовала новую сессию. При закрытом чтении сверка дала 4, отдельная попытка восстановления — 2, режим доступа и байты сохранены.
- Изолированная репетиция с синтетическим разрешением подтвердила отказ при подмене отчёта, реестра или Канидата INBOX и возобновление в восьми точках прерывания.

## Допуск

Целевое уточнение диагностики проверено при полученном результате сверки. U4 остаётся открытым из-за двух обычных смешанных прогонов, прежних требований V4 и пропущенных нативных проверок Claude Code. Следующий вопрос — как обеспечить запуск сверки в смешанном сценарии, сохраняя возможность общей выдачи always loaded правил.
