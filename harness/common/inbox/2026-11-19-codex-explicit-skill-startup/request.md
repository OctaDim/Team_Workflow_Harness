# Соблюдать порядок чтения правил при явном вызове скилла в Codex

Дата возникновения и оформления — 2026-11-19. Пакет — common. Заявка касается обязательного старта Codex и связана с блокировкой [первой заявки группы 8](../2026-11-19-01-external-operation-retries/request.md).

## Наблюдение

В Codex CLI 0.166.0 при обычном явном вызове скилла в common-only чтение правил и SKILL.md попало в одну команду. В common+project агент открыл скилл до того, как получил полные результаты отдельного чтения всех перечисленных правил. Нативные ответы по предметной задаче оказались правильными. Изолированные прогоны с детальной подсказкой о порядке прошли в обоих режимах. Причина различий между прогонами остаётся предметом проверки. [Отчёт](../../testing/evidence/2026-11-19-external-operation-retries.md) · [Данные прогонов](../../testing/evidence/2026-11-19-external-operation-retries.json)

Порядок уже задан в [START](../../START.md), [правиле чтения инструкций](../../rules/comm-instruction-order.md) и [процедуре получения полного списка правил](../../rules/comm-human-folder-guides.md). Первая заявка группы 8 описывает сбой как препятствие к выпуску своего кандидата. Вторая заявка группы касается фоновых задач. Открытой заявки на исправление общего старта при сверке не найдено.

## Требуемый результат

Обычный запрос с явным именем установленного скилла должен приводить Codex к его применению после завершения обязательного старта. Пользователю достаточно назвать скилл и задачу.

При выполнении сначала воспроизвести сбой на действующей версии. Проверить гипотезу о моменте выдачи инструкции: агент может запланировать одну длинную команду ещё до получения содержимого START. Минимальный вариант для сравнения — в успешном выводе существующей [стартовой проверки](../../checks/ensure_entrypoint_links.py) предложить следующим отдельным вызовом прочитать только оба START по порядку и дождаться их результата. Подробная процедура остаётся у действующих владельцев. Выбор исправления зависит от событий реального прогона и совместимости обычного запуска. Доступность скилла в каталоге сама по себе не свидетельствует о чтении его тела.

## Приёмка

1. В свежих установках common-only и common+project вызвать один и тот же установленный скилл обычным запросом, например `Примени $comm-retry-external-operations к потере ответа после отправки документа`. Скилл должен быть доступен в изолированной проверочной установке. Текст запроса одинаков до и после изменения и не содержит подсказки о порядке.
2. По событиям инструментов проверить успешный запуск входной проверки, чтение обоих START, отдельное получение полного рекурсивного списка машинных Markdown-правил и последующие явные чтения всех путей. Проверить полноту выданного текста, в том числе при обрезке вывода. Исключать README.human.md на любой глубине. Затем должны быть прочитаны оба INDEX по порядку. Первое чтение тела скилла или его ресурса должно происходить после получения этих результатов. Использовать существующий [аудитор чтения](../../checks/check_human_guide_search.py) и отдельно проверить последовательность START, INDEX и обращения к ресурсам в трассе.
3. Подтвердить, что скилл использован по назначению. Оценочный сценарий должен обнаруживать объединение чтения правил и скилла в одном вызове, а также пропуск одного правила. Сохранить результаты обычных прогонов по каждому режиму. Прогон с пошаговой подсказкой учитывать отдельно как диагностический контроль.
4. Если меняется стартовая проверка, проверить её обычный и ошибочный выход, повторный запуск, создание отсутствующего нейтрального project и сохранность существующего project. Применить проверенное исправление в границах отдельно разрешённых стадий.
