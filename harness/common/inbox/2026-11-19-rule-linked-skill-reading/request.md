# Читать скиллы по ссылкам из правил во время старта

Дата возникновения и создания — 2026-11-19. Пакет — common.

## Причина и результат

При разборе трассы с ранним открытием INDEX пользователь уточнил, какой переход до INDEX допустим. Сейчас правило порядка требует получить все правила до первого скилла. Это исключает и осмысленный переход к конкретному скиллу, когда основание для чтения уже известно из полученного правила. Предлагается уточнить действующий порядок и проверку трассы в common-only и common+project. [Полный кандидат правила порядка](comm-instruction-order.md)

## Согласованное поведение

1. После стартовой команды прочитать оба START.md, сначала common, затем project. Отдельно получить полный список машинных Markdown в установленной .claude/rules/ со всеми подпапками, включая скрытые и игнорируемые файлы. Исключить README.human.md на любой глубине. Сверить конкретные пути. Засчитать любое число полных актуальных чтений через START, включая весь список. Для канонической копии подтвердить соответствие пути и содержимого установленному правилу. Дочитать пропущенный фрагмент той же версии. При изменении или неизвестной актуальности прочитать текущую версию.
2. Учесть ссылки из уже зачтённых правил по полученному тексту. Остальные правила читать по одному. Получив полный текст правила, открыть отдельным вызовом только названные им скиллы, основания для чтения которых уже наступили, затем вернуться к следующему правилу. Если условие наступит позже, прочитать скилл тогда. Скилл по прямой безусловной ссылке прочитать сразу. Использовать уже полученный полный актуальный текст скилла, в том числе если на него указывают несколько правил. Соблюдать прямые запреты на раннюю загрузку. Чтение скилла само по себе не разрешает выполнять описанные действия.
3. При создании безусловной ссылки из правила на скилл или снятии условия с существующей ссылки запросить и получить явное подтверждение пользователя **до правки**. Запрос относится к конкретному изменению. При последующих стартах агент следует согласованной ссылке без повторного вопроса.
4. После последнего обязательного правила прочитать оба INDEX.md в порядке common → project. Для задачи открыть только нужные скиллы, полный актуальный текст которых ещё не получен. Массовое чтение или перечитывание всех скиллов по одному лишь факту открытия INDEX считать ошибкой.

## Что согласовать при выполнении

Порядком владеет существующее правило. Эта граница нужна уже во время старта, до выбора процедуры. Согласовать его текст с указаниями в common/START.md и правиле чтения, а также с фактическими критериями проверки трассы и её регрессиями. Проверить, что изолированная установка получает те же указания. [Действующее правило](../../rules/comm-instruction-order.md) · [Правило чтения](../../rules/comm-human-folder-guides.md) · [Проверка трассы](../../checks/check_human_guide_search.py) · [Регрессионные тесты](../../testing/tests/test_human_guide_reader.py)

При обработке использовать актуальный результат связанной заявки о повторном использовании полных чтений. Сохранить сверку путей, отдельный учёт повторов и отчёт по каждому сценарию. Изменяемый здесь критерий — допустимость обоснованного открытия скилла между правилами. [Связанная заявка](../2026-11-19-reuse-complete-rule-reads/request.md)

## Критерии приёмки

| Сценарий | Ожидаемый результат |
| --- | --- |
| Через START прочитаны ноль, часть или все правила. Одно из зачтённых правил ссылается на нужный скилл | Список подтверждён по путям. Агент учитывает ссылку и дочитывает только оставшиеся правила |
| Правило указывает на скилл перед изменением конфигурации | Для согласованной правки агент читает скилл и возвращается к правилам. При разборе истории Git скилл остаётся закрытым. Если основание появится позднее, скилл открывается тогда |
| Два правила направляют к одному скиллу. В первом условие выполнено, во втором ссылка безусловная | Первое чтение засчитано, агент продолжает обход. Одно чтение не запускает правку конфигурации или иную операцию |
| Автор добавляет безусловную ссылку либо удаляет условие у существующей | В каждом случае до подтверждения конкретная правка ожидает. После явного согласия она разрешена. На очередном старте нового согласия на чтение не требуется |
| До INDEX открыт скилл без применимой ссылки, до наступления условия или вопреки прямому запрету | Проверка отклоняет переход. Для положительного случая проверяется последовательность «завершено чтение правила → открыт указанный скилл → продолжено чтение правил» |
| Пропущен обязательный путь, отсутствует отдельное перечисление, неполный или устаревший текст выдан за актуальный, повторно прочитано неизменное правило либо преждевременно открыт INDEX | Проверка указывает конкретное нарушение. Повтор одного пути не компенсирует пропуск другого |
| После обоих INDEX задача требует ещё одного скилла | Агент открывает нужный скилл. Массовый обход каталога с чтением всех тел и массовое перечитывание отклоняются |

## Сквозной критерий приёмки по п. 1 заявки о явном вызове

В свежих изолированных установках common-only и common+project установить одну версию comm-retry-external-operations. До и после применения текущего кандидата № 5 при одной базе с опубликованным результатом № 4 передать дословно один запрос без дополнительных подсказок:

```text
Примени $comm-retry-external-operations к потере ответа после отправки документа
```

Для каждой из четырёх ячеек сохранить версии, события и два результата. По инструментам проверить успешный старт, оба START, отдельное полное перечисление, подтверждение полного актуального текста каждого пути и оба INDEX в порядке common → project. Зачесть чтения через START при доказанном соответствии пути и версии, включая два таких правила и десять последующих. INDEX до полного списка или покрытия — ошибка. До INDEX отдельное чтение скилла допускает только уже полученное правило при наступившем основании. Упоминание пользователем такого основания не создаёт. По финальному ответу отдельно оценить применение скилла к потере ответа. При сбое установить первое нарушившее событие и его причину до выбора исправления. Область — приёмка № 5 на существующем входе.
