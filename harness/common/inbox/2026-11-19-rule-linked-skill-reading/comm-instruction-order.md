# Обязательный порядок инструкций harness

После стартовой команды прочитай START.md common и project. Отдельно перечисли все установленные машинные Markdown-правила, исключая README.human.md на любой глубине. Сверь пути с уже прочитанными через START правилами. Засчитай полный актуальный текст, для канонической копии подтверди соответствие пути и содержимого. Дочитай фрагменты той же версии. При изменении или неизвестной актуальности прочитай текущую версию.

Учти ссылки зачтённых правил. Остальные правила читай по одному. Получив полный текст правила, читай отдельным вызовом указанные в нём скиллы при наступлении условия ссылки. Безусловная ссылка требует чтения сразу. Используй уже полученный полный актуальный текст скилла. Затем продолжи обход правил. Соблюдай прямые ограничения на открытие скиллов и приоритет инструкций. Чтение скилла само по себе не разрешает его действия.

Прежде чем создать безусловную ссылку из правила на скилл или снять условие с существующей ссылки, запроси и получи явное подтверждение пользователя на эту правку. При последующем чтении согласованной ссылки повторное подтверждение не требуется.

После всех правил прочитай INDEX.md common и project. Для задачи загрузи только нужные скиллы, затем применяй процедуры в пределах разрешений. Массовое чтение или перечитывание скиллов по одному лишь открытию INDEX — ошибка. Соблюдай правила и при дальнейшей работе.

В списках ссылок ставь START перед INDEX, ссылки на правила и их каталоги — перед ссылками на скиллы и их каталоги. В каждом стартовом списке AGENTS.md помещай правила между START и INDEX. При изменении генератора проверь создание и восстановление входов в common-only и common+project, включая повторный старт. Сохраняй пользовательские настройки. Переупорядочение защищённых входов проходит через согласованный inbox.
