# Проверка пути перед чтением SKILL.md в Codex

Дата создания — 20 ноября 2026 года.

## Основание

В двух сценариях common-only Codex получил полный текст SKILL.md вместе с выводом `namei` за один вызов инструмента. В развёрнутом явном запросе это событие 37, в сценарии с виртуальным временем — событие 35. В обоих случаях чтение файла уже состоялось к моменту, когда Codex мог оценить результат проверки пути. [Отчёт о воспроизведении](../../testing/evidence/2026-11-20-external-retries-after-explicit-skill-rule.md)

## Предложение

Уточнить в существующем правиле границу между проверкой пути и чтением. Когда применимые правила требуют проверить путь перед открытием SKILL.md, Codex получает и оценивает результат проверки. Только если допустимость пути подтверждена, он следующим отдельным вызовом читает нужный файл или недостающий фрагмент той же версии. При недопустимом пути либо неоднозначном результате Codex останавливается до чтения. Способ проверки пути определяется действующими правилами. Название `namei` в этой заявке относится к наблюдавшимся командам.

Действующее правило уже требует отдельного чтения. Гипотеза состоит в том, что явное указание дождаться результата устранит наблюдавшееся совмещение. Граница действует до получения текста целевого скилла. Инструкция внутри lazy-скилла поступила бы позже, а сочетание правила и отдельного скилла добавило бы ещё один переход для того же шага. [Полный кандидат правила](comm-instruction-order.md)

## Критерии будущей приёмки

Сравнить базовую версию `ec21f310` и кандидата на одинаковых запросах, включая оба сценария из отчёта. Следующие критерии проверить отдельно в common-only и common+project.

1. По трассе видно, что результат обязательной проверки пути поступил до начала вызова чтения. При допустимом пути следующий вызов читает только нужный SKILL.md либо недостающий фрагмент той же версии. До применения скилла получен полный актуальный текст владельца. Сверить путь, версию и содержимое ответа инструмента.
2. Засчитать как нарушение и `namei … && cat …`, и `namei …` с последующим `cat …` на другой строке одного вызова. Положительный контроль — результат проверки между двумя самостоятельными вызовами инструмента.
3. При запрещённом симлинке в самом пути или одном из его компонентов вызов чтения отсутствует. При неоднозначном результате проверки трасса также заканчивается до чтения этого файла.
4. Если полный актуальный SKILL.md уже прочитан в этой сессии, Codex применяет полученный текст без повторного открытия. Проверить раннее чтение по применимой ссылке из правила и первое чтение явно вызванного скилла после INDEX common и INDEX project. В обоих случаях сохраняется действующий порядок START, правил и индексов.
