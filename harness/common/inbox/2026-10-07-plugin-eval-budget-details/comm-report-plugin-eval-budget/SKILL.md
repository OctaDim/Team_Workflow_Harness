# Подробный вывод бюджета plugin-eval

Оценивай выбранную папку через установленный plugin-eval с human-фильтром;
перед запуском прочитай из корня проекта
`harness/common/skills/comm-create-lazy-claude-codex-skills/references/evaluation.md`.
Используй свежий JSON `analyze --format json`, не измеряй ресурсы повторно
другим токенизатором. Отчёт сохраняй вне анализируемой папки.

Сначала покажи штатную оценку: путь, категорию анализатора `target.kind`,
score/grade, findings, trigger/invoke/deferred/total, bands, фактические
thresholds и рекомендованные действия. Детализация дополняет этот результат.

Автоматически добавляй её при `budgets.deferred_cost_tokens.value > 1200`
для `skill` или `> 1600` для generic `directory`; равенство не превышение.
При явном запросе добавляй независимо от порога. Это пороги детализации:
если baseline анализатора отличается, покажи отличие, сохрани его band и checks.
Этот trigger относится к общему deferred; категорию суммы строки определяй
отдельно по шкале ниже. Отчёт не разрешает менять контракты.

Для каждого анализируемого скилла отдельно:

- `S` = `budgets.invoke_cost_tokens.value`: весь SKILL.md, включая frontmatter.
- `R_i` = tokens каждого текстового компонента `deferred_cost_tokens.components`
  внутри `references/`, включая вложенные и не связанные ссылками ресурсы.
- `T` (`Texts`) = сумма остальных deferred-компонентов: scripts, assets,
  настройки и другие учитываемые текстовые файлы, кроме всех references.
  SKILL.md уже исключён анализатором. README.human.md исключается до оценки.
- Выведи по одной строке на каждый reference с полным относительным путём:
  `SKILL.md=S/references/<name>=R_i /Texts=T --> S+R_i+T (категория)`.
  Например: `SKILL.md=150/references/example.md=350 /Texts=500 --> 1000 (heavy-warn)`.
- Покажи состав `Texts` по файлам и tokens по убыванию; при отсутствии —
  `Texts=0 (других учитываемых текстовых файлов нет)`. Без references выведи
  `SKILL.md=S/references=нет /Texts=T --> S+T (категория)`.
- Сверь `sum(R_i)+T` с deferred. При расхождении или недоступном JSON сообщи
  недостающие данные; неизвестное значение не заменяй нулём.

Категорию в скобках рассчитывай по сумме всей строки, независимо от baseline:

| Сумма строки | Объём | Категория вывода |
|---|---|---|
| ≤180 | небольшой | `good` |
| 181–520 | умеренный | `moderate` |
| 521–1200 | большой, warn | `heavy-warn` |
| >1200 | чрезмерный, fail | `excessive-fail` |

Выводи одну соответствующую категорию, а не перечень всех вариантов.
Это дополнительная оценка строки: её warn/fail не подменяет реальные
checks, bands и статусы проверок plugin-eval или агента.

Если превышение получено для generic-папки, сохрани её общий результат и
1600-порог; оцени каждый входящий скилл отдельно для этих строк. Для папки
без скиллов покажи компоненты по файлам: `SKILL.md=N/A`, references не назначай.
Не смешивай ресурсы разных скиллов и не считай внешний linked-файл локальным.

Подпиши единицы: статическая оценка plugin-eval, не фактический расход сессии.
SKILL.md читается при вызове; обязательный стартовый контекст включает также
другие инструкции и metadata и этой строкой не измеряется. Сумма строки —
SKILL.md + один reference + все Texts; остальные references в неё не входят.
Отдельно покажи полный deferred: суммарный размер библиотеки может превышать
порог даже при небольших отдельных строках. Не складывай строки между собой.
Бинарные/неучитываемые файлы не имеют здесь оценки. Назови крупнейшие ресурсы
как кандидаты на сжатие или разделение, сохраняя обязательное поведение;
сам отчёт не разрешает правку и не повышает статусы проверок.
