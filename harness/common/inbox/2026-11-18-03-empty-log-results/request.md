# Проверка пустой выдачи при диагностике по логам

Создано 2026-11-18 по итогам согласования группы 6, вопрос 4. Заявка 3 из 4.

## Основание

Источник: bts-transenergo-epl-server на коммите `a4eb35bf52cce0c304bff5db000330673a9d6526`. В `.claude/rules/prod-logs.md:55` локальные логи вернули пустой результат после пересоздания контейнера. История за то же окно содержала около 400 строк от трёх поколений контейнера. В `.claude/rules/prod-logs.md:259` описан отдельный риск: строки есть, но фильтр ищет путь, которого нет в работающей версии.

[comm-verify-project-facts](../../skills/comm-verify-project-facts/SKILL.md) уже требует оценивать охват, фильтры и положительные контроли. Для пустой выдачи нужен короткий ресурс с конкретной последовательностью этих проверок.

## Требуемый результат

Дополнить существующий скилл ссылкой, срабатывающей при выводе по пустой выдаче логов. Ресурс проверяет среду, сервис, экземпляры, временное окно, контрольную запись и фактический формат события без привязки к конкретному сборщику логов.

Полный [кандидат](candidate/comm-verify-project-facts/SKILL.md) содержит [новый ресурс](candidate/comm-verify-project-facts/references/empty-log-results.md) и действующие материалы Git.

## Приёмка будущего выполнения

- При перезапуске агент проверяет охват нужных экземпляров и истории. При отдельном процессе сборщик, окно и селектор относятся к нужному сервису.
- Контрольный запрос к тому же источнику за то же окно без узкого фильтра подтверждает, что есть пригодные записи, но ошибочное имя поля или событие из другой версии всё ещё выявляется отдельной сверкой.
- Если охват и контроль подтверждены, вывод ограничен проверенным потоком и интервалом. Если контроль недоступен или пробел не устранён, результат говорит, какой факт остаётся неизвестным.
- Для иных задач проверки фактов сохраняются прежние пути и условная загрузка ресурсов Git.

На стадии выполнения проверить текущую компактную версию по действующей процедуре валидации harness. Зафиксировать структурные проверки, бюджет и поведение отдельно для Codex и Claude в режимах common-only и common+project. Недоступные проверки отметить как непроверенные.
