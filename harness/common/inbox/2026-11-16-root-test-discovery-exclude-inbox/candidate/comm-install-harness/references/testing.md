# Запуск pytest

Из корня проекта, Python 3.9+ и установленный uv:

```sh
uv venv .venv
uv pip sync --python .venv/bin/python harness/common/testing/requirements.lock
.venv/bin/python -m pytest .
.venv/bin/python harness/common/scripts/run_tests.py
```

После установки обе последние команды выполняют общий прогон от корня проекта,
рекурсивно собирая тесты приложения и harness по действующим настройкам.
Ограничивать область только harness или его основным набором нельзя.
Автоматический сбор общего прогона исключает два дерева со всем содержимым:
`harness/common/inbox/` и `harness/project/inbox/`. Из корня этому соответствуют
`--ignore=harness/common/inbox` и `--ignore=harness/project/inbox`.
Стандартные исключения служебных каталогов и окружений сохраняются;
дополнительное исключение активных каталогов проекта требует основания.
Имена before/candidate/source вне двух деревьев сами по себе не исключения.
Runner не должен самостоятельно перечислять и запускать все inbox-редакции.

Для целевой проверки передай pytest проверенный существующий файл или каталог
выбранного кандидата/снимка. Явная цель внутри inbox должна оставаться доступной;
проверь это для установленного pytest и действующих collector hooks.
При смешанном запуске общего корня и inbox-цели допускаются дополнительные
inbox-наборы. Такой запуск не гарантирует исключение архивных редакций.
Указывать общий корень автоматически в отдельном целевом прогоне не требуется.

pytest выбирает одну конфигурацию; вложенные pytest.ini не объединяются
автоматически. Если выбранному набору нужен свой конфиг, укажи проверенный
существующий путь через -c и явную цель, учитывая рабочую директорию и rootdir.
Не выдавай корневой прогон за применение всех вложенных настроек.
`--import-mode=importlib` сохраняет независимость одноимённых модулей.
Пустая выборка не успех; сохраняй завершение/код pytest. Сбор без выполнения
не доказывает прохождение, целевой результат не заменяет общий.

После переноса common используй `harness/common/testing/pytest.ini` как шаблон
только при отсутствии отличающейся конфигурации принимающего проекта.
Иначе интегрируй область от корня, два исключения и нужный режим импорта в
действующий формат: pytest.ini, pyproject.toml, tox.ini или setup.cfg.
Не создавай pytest.ini, затеняющий существующие настройки, и не теряй
проектные шаблоны обнаружения, маркеры, плагины и остальные параметры.
Проверь common-only и common+project с сохранением существующего project.

Переносимый основной набор не требует сторонних pytest-плагинов; настройки и
плагины принимающего приложения сохраняй. При диагностике собственных проверок
можно задать `PYTEST_DISABLE_PLUGIN_AUTOLOAD=1`, но не скрывать этим необходимые
плагины проекта. `requirements.txt` фиксирует прямые зависимости,
`requirements.lock` — universal compile для Python 3.9 с условными зависимостями.
Зависимости тестов не нужны стартовому checker.
