## Принятые решения

Три самостоятельных lazy-скилла для поведения кода/файлов приложения, отдельно
от проверки harness. Политика А полного прогона относится только к приложению;
TDD нового кода/поведения и дефектов, достаточность проверок каждого изменения,
unit/integration новых функций, качество тестов и безопасная изоляция мутаций
сохранены. Нового always-loaded правила нет. Размер diff не освобождает от проверки.

Качество тестов → запуск → TDD — порядок создания по зависимостям. TDD использует
других владельцев по их задачам; запуск и аудит самостоятельны. Мутационный
ресурс читается только перед контролируемыми мутациями. Обязательной полной
мутационной кампании на каждую правку не вводится.
