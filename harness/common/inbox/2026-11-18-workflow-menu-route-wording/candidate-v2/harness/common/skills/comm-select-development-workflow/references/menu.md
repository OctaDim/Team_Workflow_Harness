# Route menu

Используй запрос, контекст и краткие описания. Назови этапы и причину
рекомендации. До выбора оставь процедуры закрытыми. Не выдавай краткие
описания за процедуры. Покажи все применимые и обязательные варианты
одним списком с 1. Начни с этих строк, меняй только номера:

1. **Superpowers + Compound Engineering:** `using-superpowers + ce-brainstorm → ce-plan → ce-work` - одновременное выполнение `using-superpowers и ce-`этапов
2. **Compound Engineering:**  `ce-brainstorm → ce-plan → ce-work`  - нативный ce-маршрут
3. Без специального маршрута: текущая модель c effort самостоятельно выполняет задачу.

Перед отправкой посимвольно сверь обязательные и короткие строки.
В пункте 1 — «одновременное выполнение».

В смешанном маршруте основной агент сначала применяет using-superpowers, затем
CE со своими согласованиями. Нативный CE использует свою цепочку. Делегирование
зависит от этапа CE, доступности и разрешения. Субагент игнорирует using-superpowers.

Самостоятельный маршрут сохраняет модель и effort, без делегирования и цепочек.

Короткая рекомендация идёт рядом с CE без автоматического показа полных цепочек.
Покажи все рекомендации. Если применимость не установлена, назови недостающие
данные/скиллы и покажи все короткие и полные варианты как условные, без рекомендации.
Короткие строки копируй в этом порядке, меняй только номера:

1. Обязательного плагина нет: **эксперимент → исследование → выводы**. Инструменты выбираются под согласованный эксперимент.
2. **Superpowers**, скилл `brainstorming`: **короткий дизайн → согласование → реализация и проверка.**
3. **Superpowers**, скилл `systematic-debugging`: **Диагностика → первопричина → исправление и проверка.**

Запускай эксперимент только после его согласования.

Добавь другие применимые короткие маршруты. Отметь недоступные скиллы.
При полной или неустановленной рекомендации покажи оба исполнения:

Оба полных варианта означают весь процесс: using-superpowers → brainstorming →
согласование спецификации → writing-plans → согласование плана с сохранением
выбранного исполнителя → одно из исполнений ниже → его проверки и review →
verification-before-completion → finishing-a-development-branch.
Выбор исполнителя сохраняет отдельные разрешения.

1. **Superpowers, через одного агента:** `brainstorming → writing-plans → executing-plans`.
2. Superpowers, через субагентов: `brainstorming → writing-plans → subagent-driven-development`.

При каждом показе полных цепочек скопируй блок дословно:

```markdown
> **Самостоятельная реализация не означает полного отсутствия субагентов**.
> В `executing-plans` основной агент пишет весь код сам, но скилл предусматривает
> отдельного субагента для итогового ревью, когда он доступен.
> В `subagent-driven-development` отдельные исполнители и ревьюеры участвуют
> в каждой задаче плана.
```

Вызов using-superpowers или brainstorming оставляет выбор цепочки и исполнителя
за пользователем. Короткий маршрут следует только своим этапам.
