# Добавить пространства имён в ссылки на скиллы Harness

Дата возникновения потребности и создания заявки — 2026-11-19. Пакет — common. Область — действующие правила и скиллы Harness в common и project, включая их установленные копии.

## Основание

При сравнении Superpowers и Compound Engineering разобрали короткие правила, которые вызывают отдельный скилл по точному имени. В Harness [действующий контракт авторства](../../skills/comm-create-lazy-claude-codex-skills/references/content-contract.md) требует точное имя, но не требует пространства имён. [Предыдущая заявка](../2026-11-18-skill-dependencies-by-name/request.md) закрепила поиск по имени. Пользователь попросил добавить пространство имён ко всем уже существующим ссылкам по имени и применять его при создании и изменении инструкций.

## Требуемый результат

1. Найти все действующие ссылки на скиллы по имени в правилах, `SKILL.md` и их рабочих ресурсах в common и project. Сверить канонические инструкции и установленные копии. Для каждой ссылки зафиксировать файл и место, прежнее имя, целевой скилл и применимые среды. Имена в описаниях, примерах и рабочих ресурсах учитывать там, где они выражают фактический вызов. Прямые ссылки на файлы, включая `references/`, относятся к отдельному механизму.
2. Установить, как Codex и Claude Code фактически предоставляют и разрешают полные имена локальных и плагинных скиллов. Заменить каждое имя без пространства имён на точный идентификатор с пространством имён, сохранив целевой скилл, условие, параметры и обязательность вызова. Проверить и уже квалифицированные имена. При различиях между средами зафиксировать рабочие формы для каждой. Если поддерживаемая установка не разрешает требуемую форму, зафиксировать блокировку и согласовать совместимый способ до замены затронутых ссылок.
3. Закрепить это требование в действующей процедуре авторства. При создании или изменении правила либо скилла сверять все содержащиеся в изменяемой инструкции ссылки по имени, включая уже существующие. [Предварительный кандидат контракта авторства](candidate/comm-create-lazy-claude-codex-skills/references/content-contract.md) задаёт требуемое поведение. Точные формы идентификаторов определяются при проверке установки.

## Приёмка

- Реестр покрывает все ссылки по имени в действующих инструкциях. Для каждой есть соответствие прежнего и полного имени, целевой скилл и результат проверки в каждой применимой среде. Правила и установленные копии согласованы с каноническими источниками.
- Отдельно проверить Codex и Claude Code в установках common-only и common+project. Подтвердить по фактическому разрешению каждого имени, что оно ведёт к тому же единственному скиллу. В нативных сценариях проверить, что правило или скилл при своём условии действительно загружает и применяет зависимость с прежними параметрами. Отдельно проверить совпадающие короткие имена и недоступную обязательную зависимость.
- Проверить авторство нового правила и скилла, а также правку существующего правила и скилла. В каждом сценарии ссылка по имени получает пространство имён и разрешается в целевой скилл.
- Записать результаты по версиям и режимам отдельно. Если какой-либо обязательный сценарий недоступен, отметить его как непроверенный. Проверка формата текста или наличия имени в списке сама по себе не подтверждает вызов.
