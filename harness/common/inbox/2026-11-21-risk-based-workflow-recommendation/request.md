# Обосновывать выбор маршрута риском задачи и учитывать порядок сохранения решений

Дата создания и возникновения потребности — 2026-11-21. Пакет — common.

При обсуждении миграции harness для Codex и Claude Code агент рекомендовал вариант 3. Основанием послужила просьба пользователя разбирать вопросы по одному. Хотя уже было известно о различиях двух клиентов и пропусках этапов, рекомендация не объясняла, как обнаружить расхождение в их поведении. После уточнения о подробном плане, проверках и сохранении каждого принятого решения агент рекомендовал вариант 1. Последнее предпочтение явно прозвучало только при уточнении.

## Предложение

Изменить раздел рекомендации в контекстном lazy скилле `comm-select-development-workflow`. Для открытого выбора связать существенный риск задачи с конкретным этапом или проверкой маршрута. Просьба «согласовывай по одному вопросу» определяет порядок общения и сама по себе недостаточна для выбора варианта 3. Если неизвестное предпочтение меняет рекомендацию, задать один конкретный вопрос. Уже известное предпочтение учитывать сразу. Номер рекомендуемого маршрута зависит от задачи.

Для будущих многоэтапных задач этого пользователя предложено отдельно сохранять каждое явно принятое решение до следующего вопроса: что принято, основание и критерий проверки. При исполнении согласовать с пользователем постоянное место и разрешение на запись с учётом области действия предпочтения. Запись только в этой временной заявке недостаточна для будущих сессий. Персональное предпочтение не распространяется на всех пользователей common.

Полный кандидат приложен в [comm-select-development-workflow/](comm-select-development-workflow/). Единственная содержательная правка — в [references/menu.md](comm-select-development-workflow/references/menu.md). Действующий контекстный lazy скилл уже выбирается при открытом выборе маршрута. Дополнительное always loaded правило или короткое always правило со скиллом увеличило бы стартовый контекст для задач, которым меню не требуется.

## Как проверить при исполнении

1. В свежих сессиях дать две задачи с одинаковой фразой «согласовывай по одному вопросу»: локальную обратимую правку и миграцию загрузки harness в Codex и Claude Code. Для каждой агент объясняет рекомендацию через конкретный риск и достаточную проверку. Для миграции учитывает проверку загрузки каждым клиентом, для локальной правки достаточно соразмерной проверки. Оценивать обоснование, а не номер пункта.
2. Повторить со значимым неизвестным предпочтением и с уже известным. В первом случае агент задаёт один вопрос до рекомендации. Во втором учитывает ответ без повторного вопроса. Если пользователем согласовано постоянное сохранение решений, после явно принятого решения и до следующего вопроса проверить запись в согласованном месте и её доступность в новой сессии.
3. Проверить, что явный выбор маршрута по-прежнему принимается без повторного меню. Для будущей публикации провести применимые проверки отдельно в Codex и Claude Code, при установке только common и при установке common вместе с project.

## Уточнение области действия — 2026-11-24

Порядок записи решений действует и при разработке шаблона Team Workflow Harness, и в приложениях, где он используется. До следующего вопроса по многоэтапной задаче сохраняется каждое явно согласованное решение, его основание и критерий проверки. Связанные решения можно вести в одном файле. Пакет определяется предметом решения: `harness/common/decisions` для шаблона, `harness/project/decisions` приложения для его решений. Свежая сессия находит запись в нужном пакете и продолжает с первого открытого вопроса.

Полный кандидат включает [правило сохранения состояния](rules/comm-user-owned-entrypoints.md) и [скилл выбора маршрута](comm-select-development-workflow/). Правило содержит короткое требование до следующего вопроса, поскольку контекстный скилл выбора маршрута может не открываться в продолжении или при уже выбранном маршруте. Отдельный скилл для записи и восстановления не нужен: действия укладываются в правило, а классификацию и разрешения на запись определяют существующие процедуры. Выбор маршрута остаётся в контекстном скилле.
