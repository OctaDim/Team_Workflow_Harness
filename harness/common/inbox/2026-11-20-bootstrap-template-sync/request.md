# Синхронизировать шаблоны BOOTSTRAP и проверить старт с новым AGENTS.md

Дата обращения и создания — 2026-11-20. Пакет — common.

## Основание

При сравнении [генератора входа](../../checks/ensure_entrypoint_links.py) с [корневым AGENTS.md](../../../../AGENTS.md) обнаружено расхождение. В BOOTSTRAP осталось октябрьское требование прочитать все правила до первого скилла. Опубликованные [START](../../START.md) и [правило порядка](../../rules/comm-instruction-order.md) требуют переходить от полностью прочитанного правила к указанному скиллу, как только для этого есть основание. В [ноябрьской серии из 12 прогонов](../2026-11-19-rule-linked-skill-reading/request.md#проверка-подсказки-после-успешной-стартовой-команды) использован существующий AGENTS.md.

Связанная [заявка о явном вызове скилла](../2026-11-19-codex-explicit-skill-startup/request.md) проверяет старт Codex. При выполнении сверить её результаты и использовать применимые трассы с подтверждённым происхождением входа.

## Требуемый результат

1. Привести BOOTSTRAP для AGENTS.md в соответствие с актуальной процедурой чтения. Сгенерированный вход должен вести к действующим START и правилам. Уже полученное правило может потребовать отдельного чтения скилла до первого INDEX. Безусловная ссылка действует сразу, условная — при наступлении условия. Перед первым INDEX обязательны полный список установленных правил и подтверждённое чтение каждого пути. Сохраняется порядок common перед project.
2. Выявить все действующие шаблоны BOOTSTRAP, включая встроенные в генераторы. Для каждого указать, какой файл он создаёт и какие файлы harness или части соответствующего файла определяют его содержимое. Сверить весь набор и устранить существующие расхождения. Исторические снимки, свидетельства и кандидаты inbox сохраняют зафиксированные версии. Синхронизация направлена от действующих источников к шаблонам и сохраняет пользовательские настройки уже существующих входов.
3. При изменении harness или соответствующего файла автоматически определять затронутые шаблоны и синхронизировать их в рамках того же изменения. Отдельная команда и подтверждение пользователя для синхронизации не требуются. При независимом изменении шаблоны сохраняют прежнее содержимое.
4. После синхронизации выводить пользователю информационное сообщение. Указать изменившиеся источники, пути обновлённых шаблонов, соответствующие генерируемые файлы и кратко перечислить изменения. При частичном выполнении явно сообщить, что обновлено и что осталось несогласованным.

## Приёмка

- Подготовить две независимые установки. В первой перенести только common и дать штатному старту создать нейтральный project. Во второй перенести common и существующий project. Зафиксировать отсутствие корневого AGENTS.md в каждой установке до запуска. Штатной проверкой сгенерировать файл и сохранить его текст и контрольную сумму. Проверить сохранность существующего project во втором режиме.
- В каждом режиме начать свежую сессию Codex с этим сгенерированным AGENTS.md и обычным явным запросом к установленному скиллу. В запросе не подсказывать порядок старта. По событиям инструментов подтвердить чтение обоих START, обработку ссылок из правил при наступлении основания, отдельное перечисление и полное покрытие правил до INDEX, затем чтение обоих INDEX и применение запрошенного скилла. Проверить случай, когда одно из правил требует прочитать скилл до следующего правила. Повторный запуск должен сохранить корректный вход. Результаты и трассы привести отдельно по каждому режиму.
- Проверить автоматическую синхронизацию изменением источника в обычном рабочем процессе. Охватить изменение инструкции harness и изменение соответствующего файла, от которого зависит шаблон. Сопоставить перечень фактически обновлённых шаблонов с ожидаемым, проверить новое содержимое и генерацию из него. Убедиться, что сообщение описывает фактический состав изменений и процесс завершается без запроса согласия. При повторе без изменений шаблоны побайтно стабильны. Несвязанная правка не создаёт ложного отчёта об обновлении.
