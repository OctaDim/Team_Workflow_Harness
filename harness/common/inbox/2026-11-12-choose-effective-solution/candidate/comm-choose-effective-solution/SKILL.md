# Choose an effective solution

Inputs: required outcome, constraints, existing solution, evidence and prior decisions.

1. Inspect relevant code, knowledge and available capabilities. Research existing
   and current alternatives; prefer suitable project mechanisms, standard/platform
   features and installed dependencies when they meet the need.
2. Identify a demonstrated gap or bottleneck. Propose installation, replacement,
   modification or new code only for a justified improvement or unmet need.
3. Compare a few best materially different options, including the existing baseline
   where present and suitable modern alternatives. Verify versions and claims
   against current primary sources. Compare effectiveness, compatibility, cost,
   maintenance and migration; use authorized measurements when necessary.
4. Recommend the best complete solution for these constraints. Explain the benefit;
   recency or a shorter implementation alone is insufficient. Retain an adequate
   baseline when improvement is unsupported; do not invent comparison results.
5. Preserve prior approvals/delegation; obtain required decisions before changes.
   Record deliberate simplifications with their applicability limit and review
   condition. Preserve safety, validation, error handling and accessibility.

Done: options, evidence, tradeoffs, recommendation and open decisions are clear.
Selection does not authorize installation or implementation.
