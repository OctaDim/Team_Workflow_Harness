## Проблема, причина и цель

Начальный абзац действующего comm-confirm-development-workflow.md требует
определить и показать маршруты перед новой задачей или набором задач без
различения аналитики и реализации. Заключительный абзац требует снова спрашивать
перед новой задачей. Из-за этого чтение, аудит, объяснение и подготовка предложений
также вызывают меню и ожидание ответа, добавляя задержку и расход токенов.

Цель — сохранить обязательный выбор маршрута перед реализацией, исключить
ненужное согласование аналитической работы и определить границу перехода
от исследования к изменениям. Отдельные разрешения других процедур сохраняются.

## Требования к будущему исправлению

1. Чтение, аудит, объяснение, исследование, диагностика и подготовка предложений
   в чате выполняются без меню маршрутов и ожидания выбора. Применимые инструкции
   и явно запрошенные навыки сохраняют силу; аналитическая классификация не
   разрешает пропускать обязательный старт и чтение применимых материалов.

2. Для реализации изменений кода, файлов, конфигурации, зависимостей или внешних
   систем выбор маршрута остаётся обязательным до начала реализации. Служебные
   записи, отдельно разрешённые пользователем для подготовки работы, включая
   создание этой заявки, сами по себе не запускают меню. Исключение ограничено
   разрешённой подготовительной записью и не разрешает исполнение её содержания.

3. В смешанной задаче разрешено сначала выполнить исследование без изменений.
   Перед переходом к реализации агент показывает выводы, границы предлагаемых
   изменений и меню маршрутов, затем ждёт выбора. До выбора реализация не начинается.

4. Однозначно указанный пользователем маршрут считается выбором, в том числе
   указанный в исходном поручении. Повторно спрашивать его или требовать выбора
   только из заново показанного меню не нужно. Неоднозначность требует уточнения
   и ожидания; неизвестный номер и конфликт номера с названием не считаются выбором.

5. Выбор действует для продолжений того же согласованного набора работ. Вопрос,
   уточнение, статус, смена хода или сжатие контекста сами по себе не создают новую
   задачу и не сбрасывают выбор. Для отдельной новой задачи реализации требуется
   новый выбор; если он уже однозначно дан пользователем для новой задачи,
   повторный вопрос также не нужен.

6. Если аналитическая работа выявила необходимость исправлений, агент сообщает
   о них. Наличие находки само по себе не разрешает реализацию. Предложение
   исправить, готовый вывод или служебная заявка не заменяют разрешение изменений.

## Сохранение меню и границы изменения

Там, где выбор маршрута действительно требуется, сохранить существующие варианты
и требования к их представлению: единый нумерованный список со сквозной нумерацией,
основания рекомендаций, обязательные дословные варианты Superpowers + Compound
Engineering, нативный Compound Engineering и вариант без специального маршрута;
условия показа коротких и полных маршрутов Superpowers, различение способов
исполнения и предупреждение об участии субагентов для полных цепочек.
Сохранить семантику сочетания скиллов, ограничения делегирования и модели/effort,
правила неоднозначного ответа и ожидание выбора там, где он ещё не получен.
Уточнить только область срабатывания меню, принятие заранее данного выбора
и сохранение выбора согласованного набора работ.

Не расширять исправление на другие согласования, защиту evidence, отдельные
разрешения создания/исполнения/публикации inbox, спецификации/планы, ограничения
среды или внешних операций. Выбор маршрута не заменяет эти разрешения;
отсутствие меню для аналитики их не отменяет. AGENTS.md, CLAUDE.md, project,
общий skeleton, чужие заявки и исходные evidence не входят в изменение.

| Сценарий | Ожидаемое поведение |
|---|---|

| Подготовка предложения в чате | Предложение подготовлено без меню; реализация не начата. |
| Отдельно разрешено создание служебной заявки | Только разрешённая запись создана без меню; исполнение и публикация не начаты. |
| Запрошена реализация без выбранного маршрута | Показано установленное меню, запрошен выбор; до ответа изменений нет. Проверить код, файлы, конфигурацию, зависимости и внешние системы. |
| Смешанный запрос на исследование и реализацию | Сначала допускается исследование без изменений; затем выводы, границы и меню; реализация ждёт выбора. |
| В исходном запросе однозначно задан маршрут | Выбор принят без повторного вопроса; остальные разрешения проверяются независимо. |
| Ответ неоднозначен, номер неизвестен или название конфликтует с номером | Уточнение и ожидание; автоматического выбора нет. |
| Продолжение того же набора после вопроса, уточнения, статуса, смены хода или сжатия контекста | Ранее согласованный маршрут сохраняется; повторного вопроса нет. |
| Новая отдельная задача реализации | Требуется новый выбор для неё; прежний не переносится автоматически. Уже однозначно заданный новый выбор принимается. |
| Аудит обнаружил дефект | Агент сообщает о находке; без разрешения реализации исправлений нет. |
| Явно запрошен применимый навык | Навык и его применимые требования сохраняются; отсутствие меню не служит их отменой. |
| Выбор маршрута действительно нужен | Состав, дословные обязательные альтернативы, нумерация и условия показа/предупреждения меню сохранены. |
| Отдельные согласования и защищённые операции | Маршрут не заменяет разрешения PR, inbox, публикации и evidence; аналитическое исключение не расширяет права записи. |

После отдельно разрешённой подготовки итогового кандидата выполнить применимые
проверки структуры, ссылок, human-фильтра, компактности/бюджета правила,
соответствия canonical/native и поведения по comm-validate-harness-instructions.
Проверить оба режима установки и повторный старт. Структурные проверки не
считать доказательством поведения; недоступные проверки оставить not run /
непроверенными. Правка версии сбрасывает относящиеся к ней статусы.
Будущие постоянные результаты сохранять вне inbox в соответствующих категориях
common через разрешённую обработку; публикацию выполнять отдельно по её гейту.
