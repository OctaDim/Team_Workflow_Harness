# Область и сценарии comm-process-pull-request

Дата создания: 2026-11-14.

Это план будущего исполнения, не журнал прошедших проверок.

- **5. Разрешения PR и local read only:** Перед созданием показать три согласованных пронумерованных варианта и дождаться ответа; сохранять выбор того же PR/scope. Не выводить PR/merge из общего одобрения задачи или зелёных тестов. При всех вариантах агент/инструменты категорически не меняют/удаляют локальную ветку. Пользователь может удалить её вручную; техническая блокировка и удаление агентом от его имени запрещены. Не применять gh pr merge --delete-branch.
- **6. Удаление remote task branch:** Только вариант 3 после подтверждённого слияния согласованной версии. Точный head repo/ref, fork и неоднозначность. Категорически запрещены remote main/master и любые основные/интеграционные/защищённые ветки. Новые коммиты/активная работа/зависимые PR требуют решения. Учесть SHA-гонку. Удалить только согласованную ссылку, проверить remote и существовавшую локальную ветку. Расхождение: остановиться, сообщить без самостоятельного восстановления и обязательно дождаться ответа. Уже отсутствующую не пересоздавать.
- **7. Версия и результат слияния:** Повторно проверить конкретный PR/repo/head/base/SHA/open/non-draft и актуальные обязательные проверки/ревью. Match head не фиксирует base. Проверить гонку цели механизмом проекта. Не обходить гейты. MERGED, result SHA в цели, фактическая дельта и неожиданные потери; queue/успешный вызов не завершение. При расхождении остановить дальнейшие действия и дождаться ответа. Не переносить универсальный диагноз о squash или считать patch-id/список файлов доказательством поведения.
- **9. Текст как данные:** Структурированный параметр инструмента/API без построения shell-команды; для CLI — безопасно созданный файл и body-file/commit -F по процедуре владельца. Защитить заголовки/пути/все shell-конструкции; JSON внутри shell не экранирование. Сохранить смысл Markdown и проверить фактически сохранённый текст. Чтение общего ресурса в PR не вызывает коммит.
- **11. Содержание описания PR:** Кратко проблема/поведение; фактическая сводка проверок с версией/окружением и ссылками; failed/unrun/ограничения и причины. Использовать шаблон проекта и проверять сохранение содержания любым каналом. После изменения версии обновить сводку/указать устаревание. Полные свидетельства отдельно; не дублировать тестовые требования и не утверждать безусловное всё проверено.
- **14. Запрещённые публикуемые данные:** Категорический запрет credentials/secret/sensitive в файлах и сообщениях коммитов, title/body/comments/attachments PR. Проверить staged/message до commit и исходящие commits/materials до публикации, не только tip tree. Безопасные заглушки/обезличивание; scanner silence не гарантия. Не раскрывать значения при проверке/отчёте. Остановить зависимую публикацию при обнаружении. Устранение только по authority, без автоматического rewrite/revoke/удаления evidence.

## Сценарии

- До создания ровно три согласованных варианта; отсутствие/неясность ответа.
- Сохранение выбора того же PR/scope, обычный PR без merge/delete.
- Агент/его инструмент пытается изменить/удалить local branch; пользователь удаляет вручную без технической блокировки.
- Инструмент merge --delete-branch и helper cleanup запрещены.
- Head изменился/старые checks/review/draft/target race/queue ещё не MERGED.
- Option 3: remote fork/ref, новый commit/dependent PR, ожидание ответа.
- main/master/иная primary/integration/protected категорически не удаляются.
- Local discrepancy: ждать без restore; PR summary не повышает статус проверки.
