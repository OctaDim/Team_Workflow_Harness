Уже отсутствующую не пересоздавать.
- **7. Версия и результат слияния:** Повторно проверить конкретный PR/repo/head/base/SHA/open/non-draft и актуальные обязательные проверки/ревью. Match head не фиксирует base. - **11. Содержание описания PR:** Кратко проблема/поведение; фактическая сводка проверок с версией/окружением и ссылками; failed/unrun/ограничения и причины. Использовать шаблон проекта и проверять сохранение содержания любым каналом. После изменения версии обновить сводку/указать устаревание. Полные свидетельства отдельно; не дублировать тестовые требования и не утверждать безусловное всё проверено.
- **14. Запрещённые публикуемые данные:** Категорический запрет credentials/secret/sensitive в файлах и сообщениях коммитов, title/body/comments/attachments PR. Проверить staged/message до commit и исходящие commits/materials до публикации, не только tip tree. Безопасные заглушки/обезличивание; scanner silence не гарантия. Не раскрывать значения при проверке/отчёте. Остановить зависимую публикацию при обнаружении. Устранение только по authority, без автоматического rewrite/revoke/удаления evidence.

## Форма и отсутствие дублей

- Rule-only: недостаточен для входов, условных действий и наблюдаемого результата; общий алгоритм не переносится в always loaded.
- Lazy-only: выбран. Явный task trigger и when-read ресурсы должны обеспечивать загрузку в нужном действии; фактическая discovery пока не проверена.
- Rule + lazy: новый ранний guard не добавляется без подтверждённого провала до выбора процедуры. При таком провале сначала проверить/уточнить metadata, затем отдельно согласовать форму.
- Reuse-only: общие факты, разрешения, тесты, evidence и конфигурация остаются существующим владельцам. Здесь сохраняется только адресованный пробел.

Результат проверки формы сейчас — обоснованный кандидат, не доказанная работоспособность.
Согласованные исторические и технические уточнения сохранены в общей карте:
никакого универсального origin/main, Linear или автоматического PR→merge;
нет универсального диагноза squash, неверной трактовки git cherry или фильтра diff.
