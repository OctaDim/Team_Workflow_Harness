# Verify current project facts

Inputs: claim, decision, project/version/environment and authorized evidence.

1. Inspect relevant current code, configuration, research, decisions, requests
   and connected sources. Reuse findings after checking applicability.
2. Separate observation, intended contract and hypothesis. Recheck material
   dated claims against authoritative current evidence; old documents/statuses/
   successes alone do not prove today's state.
3. Bound absence searches by relevant locations/naming variants, coverage,
   filters and positive controls where available. Incomplete/failed searches
   establish uncertainty, not absence; qualify conclusions.
4. Establish availability through an authorized safe operation when needed.
   Catalog/health alone is insufficient. Missing permission/evidence remains
   unresolved; never bypass restrictions.
5. For Git base/revision claims read [base state](references/git-base-state.md);
   for remaining integration work read [integration](references/git-integration.md);
   after ambiguous Git/PR outcomes read [operation result](references/git-operation-result.md).
6. Report sources/version/date, observations, contradictions, limits and supported
   conclusions. Identify affected current statements when facts change. Follow
   recording/evidence routes and preserve history.

Done: current supporting evidence or explicit unresolved facts.
Solution choice, repair and mutation authority remain separate.
