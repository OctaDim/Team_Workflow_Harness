# PR и коммиты — разбор (гайд)

> Жёсткие инварианты — в `.claude/rules/git-pr.md`. Здесь — «почему» и датированные замеры.

## Переезд в организацию 25.08.2026 — что переехало само, а что нет

Метод — **нативный GitHub Transfer**, не `clone --mirror` + `filter-repo`. Это важно: соседний
`bts-holding` переезжал вторым способом (чистили секреты подрядчику), история переписалась, вышло
два разошедшихся репозитория, и вопрос «какой канон» тянулся месяц. Здесь чистка не требовалась —
Сергей и Олег уже имели `write` и всю историю видели.

**Переехало само:** SHA, ветки, теги, открытые PR, issues, коллабораторы, форк; старый путь
редиректит (тот же `id=1259320417`, у `jojoprison` репозиториев с таким именем ноль). Переносить
было нечего: секретов, вебхуков, deploy-ключей и environments у репо **не существовало вовсе** —
деплой идёт на self-hosted раннере, ключи лежат на сервере.

**Раннер переехал вместе с репо** (регистрация по id репозитория, не по имени владельца):
проба `runs-on: [self-hosted, prod, transenergo]` взята за 7 с, следом прошёл полный боевой
деплой `deploy-20260825-11` — все шесть шагов зелёные. 🛑 При этом `.runner` на проде хранит
**старый** `gitHubUrl`: сегодня это ни на что не влияет, но сломает переустановку раннера — а
именно ею чинят прод, когда деплой встал. Перерегистрируешь — имя systemd-юнита станет
`actions.runner.ooo-bit-company-…`, и три команды в `transenergo-deploy.md` придётся править.

**Замер биллинга, который читается наоборот.** CI соседнего `ooo-bit-company/epl` падал за 3 с
с формулировкой «recent account payments have failed **or your spending limit needs to be
increased**» — она звучит как проваленный платёж, а на деле у орги просто выбран бесплатный
лимит: `usageItems` за август — `overhaul` 1938 Linux-минут + 37 Windows (те считаются вдвое),
итого ~2012 из 2000. Сам `epl` не потратил ни минуты: его джобы блокировались с первого прогона.
Отсюда два следствия: выключение CI фронта не вернёт ничего, а self-hosted работает, потому что
минут не расходует вовсе.

**Что НЕ переезжает и требует рук:** Linear GitHub App (в орге его нет — замер
`gh api orgs/ooo-bit-company/installations` отдаёт только `claude`, `claude-design-import`,
`chatgpt-codex-connector`); fine-grained PAT'ы скоупятся на владельца ресурса и умирают
(classic с `repo` — переживают); форк приватного репо повторно не создать
(`members_can_fork_private_repositories: false`); видимость держится только явными строками
коллабораторов (`default_repository_permission: none`).

**Свип по слову-владельцу у́же предмета.** Искать надо не только `jojoprison`, но и SSH-форму
`git@github.com:`, `raw.githubusercontent.com`, `api.github.com/repos`, ссылки `/pull/N`. И
разделять три класса вхождений, которые выглядят одинаково: действующий факт (править),
датированный архив (лид-маркер в шапке, тело не трогать) и **верное** упоминание — почтовый ящик
`jojoprison@`, имя человека, имя systemd-юнита. Отдельно: `docs/HANDOFF.md` держит состояние в
ДВУХ местах, и стоячий недатированный референс-блок в середине файла читается как текущее —
25.08 старый адрес нашёлся именно там, свипом, а не глазами.

## Почему текст только файлом: zsh раскрывает бэктики

zsh раскрывает `` `команда` `` **внутри двойных кавычек**, и в наших описаниях бэктики стоят в
каждой второй фразе (имена функций, файлов, полей API) — класс срабатывает не на экзотике, а на
самом обычном тексте. **Отказ тихий наполовину:** PR создаётся, ссылка печатается, всё выглядит
успешным; дыры видны только если открыть описание и перечитать — а его никто не перечитывает.

**Замер 09.08.2026 — ДВА раза за одну сессию, при известном правиле:**
- PR #415: выполнилось `uvicorn.access`, в описании осталась дыра на месте слова;
- PR #423: выполнилось шесть кусков (`number`, `validity.badInput`, `maximumAge:`,
  `client_event_id`, `API`), из них `ruff` и `curl` реально запустились — оба напечатали справку
  и ничего не сломали, но это была случайность содержимого, а не защита.

`deploy-*`. (До 25.08.2026 репозиторий жил в личном `jojoprison`; замеры ниже сняты тогда,
и в них встречается старый путь — это история, а не действующий адрес.)

## Force-push не стирает объект — замер

**Замер 22.08.2026 (TE-66).** Коммит `40564db` вытеснен force-push'ем из ветки
`szarkan/te-66-owner-sheet-mirror`. При этом:

```
gh api repos/OWNER/REPO/contents/src/logistics_bot/config.py?ref=40564db
→ строка 308: default="<идентификатор Google-таблицы>"
```

И `git log`, и веб-морда ветки показывают чистую историю, потому что смотрят на неё, а не на
объекты. Настоящее удаление объекта делает только GitHub Support (сборка мусора); своими силами
из репозитория недостижимо.

## Ненулевой код gh — замер

**Замер 22.08.2026:** `gh pr merge 646 --squash` смержил PR (`state=MERGED`, `e896d27`), а единица
пришла от следующего `gh pr view`, упавшего с
`Post "https://api.github.com/graphql": dial tcp 140.82.121.6:443: i/o timeout`. Таких таймаутов
к `api.github.com` за одну сессию поймано три — не экзотика.

## `gh pr edit` МОЛЧА не применяет body — замер (25.08.2026, PR #696)

`gh pr edit --body-file` вернул `rc=1` на deprecated Projects-classic GraphQL
(`repository.pullRequest.projectCards`), и описание при этом не обновилось. Три попытки
`gh pr edit` подряд — body оставался прежним 3003 байта; `gh pr view --json body` показывал
СТАРЫЙ текст. Симптом маскировался под `i/o timeout` и строку deprecation-warning. Сработал
обход прямым REST: `gh api -X PATCH repos/OWNER/REPO/pulls/N -F body=@<файл>` (текст файлом,
не argv). Применение подтверждать отдельным read (`gh api …/pulls/N --jq .body | grep <маркер>`),
а не кодом возврата `gh pr edit`.

## Родственное

Тот же класс, что запрет `obsidian create content="…"` с markdown и heredoc без кавычек
(`~/.claude/CLAUDE.md`): шелл не должен видеть содержательный текст вообще. Разница лишь в цене —
здесь это не выполненная чужая команда, а молча испорченный документ, по которому принимают решение.

## Ahead N и `git cherry` — замер 31.08.2026

Сессия началась с вопроса владельца: «лежит 13 коммитов, почему PR не сделали, весь день
хуячил ради того чтобы это всё осталось на компе?». Число 13 отдал `git status`
(`ahead 13` относительно **устаревшего remote-указателя ветки**, не относительно `main`).

**Что показал разбор.** Относительно `origin/main` коммитов было шесть. Из них девять
(вместе с мержем) приехали в ветку мержем свежего `main` — то есть чужая уже смерженная
работа PR #836–#844. Ещё один, докс-коммит, был выпущен как PR #835 **squash'ем**: в `main`
лежала его склейка с другим SHA, локальный оригинал остался висеть и читался как
неопубликованный. Реальной новой работы — четыре коммита фронтенда TE-224.

**Второй, более дорогой промах — в самой проверке.** Свип по всем 50 локальным веткам через
`git cherry origin/main <ветка>` дал 23 ветки «с уникальными коммитами». Проверка содержимого
поимённо оставила **одну** (`szarkan/te-263-rules-and-gitignore`). Остальные 22 были выпущены
squash'ем и просто не удалены после мержа.

**Третий промах — попытка починить замер диффом.** Метрика «сколько файлов ветки отличается
от `main`» дала осмысленные на вид числа (`real=38`, `real=21`), но мерила отставание ветки:
на ветке от 26.08 «+» строки — это старый код, который `main` с тех пор выбросил
(`console_owner_pwa`: 2 упоминания в ветке против 5 в `main`, потому что редирект заменили
самохостингом в PR #785). Все три метрики — счёт коммитов, `git cherry`, дифф — врут в одну
сторону: завышают объём «потерянного».

**Что сработало.** Сверка с `gh pr list --state all --limit 200` по имени ветки, а для веток
без PR — проверка обещанного в `main` поимённо. Для PR #719 это был список из десяти пунктов
(ручка `/api/v1/owner/blocks`, страница `/console/owner`, `te5-owner.js`, удаление
гуглописателя, зеркало листа, DOM-стенд, тесты, спека, ADR-014, правило) — все десять нашлись
в `main`, PR закрыт как перекрытый.

**Цена.** Ложная тревога «работа потеряна» стоила владельцу вечера в конце дня. Обратная
ошибка дороже: та же метрика с тем же успехом спрячет реальную невыпущенную ветку среди
двадцати двух выпущенных.
