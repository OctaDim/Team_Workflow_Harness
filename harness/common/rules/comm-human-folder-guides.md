# Границы чтения и поиска

До поиска, чтения или загрузки контекста исключи `README.human.md` на любой глубине. Его тело предназначено людям; исключай из контекста, импортов, индексирования для агентов, description и сборщиков. Используй `-g '!README.human.md'` и передавай в cat только явные пути машинных файлов. Глоб `*.md` недостаточен даже при отсутствии пояснений. Личная процедура исключение не отменяет. Программная проверка может читать тела, возвращая только пути, ошибки и результат.

Если нужно установить состав always loaded правил, можно выполнить из корня проекта:

```sh
rg --files --hidden --no-ignore .claude/rules -g '*.md' -g '!README.human.md'
```

Полноту получения файлов проверяй по `harness/common/rules/comm-instruction-order.md`. Список включает вложенные и игнорируемые Markdown любых имён. Его полнота и получение текстов — отдельные факты.

По умолчанию используй кликабельную Markdown-ссылку от каталога документа. Подпись — точное имя файла с расширением или каталога с сохранением регистра. Опускай title и пояснения в кавычках. После замены проверь все действующие ссылки. Если канонический файл и установленные копии должны совпадать по SHA-256, запиши во всех копиях один и тот же путь от корня репозитория в одинарных обратных кавычках без начального `/`. Для чтения пиши «Прочитай файл», для открытия каталога — «Открой каталог». «Запусти» и «Выполни» означают исполнение скрипта или команды. Обратные кавычки оформляют путь. При расхождении целей согласуй решение. Актуальные материалы ищи в соответствующей канонической категории. Исключи поддеревья INBOX и evidence из общего поиска по содержимому. Для выбора заявки сначала извлеки только поля статуса, затем открой применимую незавершённую заявку. Завершённую открывай по конкретному результату, расхождению или вопросу об истории. По такому же конкретному основанию открывай evidence и исторические снимки. Разрешены выбранный актуальный Канидат INBOX и свидетельства, необходимые для его проверки. Историческая или неопубликованная версия не определяет текущее поведение.

Согласованные категории создавай заранее, даже пустые. Каждой новой папке harness нужен `README.human.md` с простым пояснением и примером. В пустой папке пример иллюстративный. Наличие пояснения не подтверждает наполнение или проверку.

При оценке выводи для каждого запуска, клиента, режима и сценария шесть строк: впервые получено нативно, впервые открыто явно, размер списка, число уникальных полностью полученных путей, лишние полные чтения, результат со всеми причинами и фактическими числами. Отмечай способ получения и отдельно наблюдаемое применение. Неизвестные значения обозначай как непроверенные.

Для оценки материалов harness перед инструментами прочитай файл `harness/common/skills/comm-validate-harness-instructions/SKILL.md`.
