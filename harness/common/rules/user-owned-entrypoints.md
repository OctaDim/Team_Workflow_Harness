# Пользовательские входные файлы и динамические знания

- `AGENTS.md` подключённого проекта — статичная пользовательская настройка. Его создаёт и изменяет только пользователь вручную либо через нативный UI приложения. Агент читает этот файл, но не создаёт, не дописывает, не заменяет, не перемещает, не удаляет и не перегенерирует его; установка harness и исправление ошибки не дают такого права.
- `AGENTS.md` не содержит динамических данных: состояния задач, handoffs, результатов текущих прогонов, истории сессий или новых уроков. Не обходи границу через генератор, хук, команду shell или другой агент.
- Корневой `CLAUDE.md` содержит ровно одну строку `@AGENTS.md`, без других инструкций и данных. Это относительный импорт соседнего корневого `AGENTS.md`; не заменяй его абсолютным машинным путём. Конечный перевод строки допустим.
- Все динамические знания и состояния, сохраняемые агентами, размещай только в соответствующих папках и файлах harness. Передача незавершённой задачи — `handoffs/`; другие категории выбирай по собственному индексу пакета. Не дублируй память в корневых входных файлах или личных каталогах.
- Если для подключения или восстановления нужна правка `AGENTS.md`, подготовь предложение внутри harness и передай пользователю для ручного применения или применения через нативный UI. Сам файл не исправляй. Отсутствующий или неподключённый пользовательский вход не считай рабочей установкой.

**Fails-when:** агент изменил пользовательский `AGENTS.md` любым способом, записал в него данные сессии, расширил однострочный `CLAUDE.md` либо сохранил динамическую память за пределами harness.

Это контракт поведения; наличие Markdown-правила не доказывает блокировку записи инструментами или настройку автоматической памяти нативного приложения.
