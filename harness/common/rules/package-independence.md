# Независимость и контекст пакетов harness

Обязательный структурный контракт:

1. `harness/common/` и `harness/project/` комплектны и работают независимо. Каждая содержит собственный индекс, необходимые процедуры, ресурсы и проверки. `common/` не требует проектных файлов; `project/` не требует файлов, скиллов или скриптов `common/`.
2. Приёмка охватывает три режима: только `common/`, только `project/`, обе папки вместе. Успешный совместный запуск не доказывает независимость каждой.
3. Каждую папку копируют отдельно в чистый временный проект. Проверяют ссылки, доступность процедур и запуск проверок без доступа к соседней папке и исходному репозиторию. Личные настройки и глобальные скиллы автора не должны скрывать отсутствующие ресурсы.
4. Для каждого режима ограничивают и проверяют стартовый контекст; при совместном подключении учитывают сумму. На старте читают короткие обязательные ограничения и указатели; подробности — по задаче; инструкцию подключения — при установке или диагностике. Комплектность файлов не требует загрузки всех файлов.
5. Одинаковые знания между папками не дублируют. В совместном режиме материалы дополняют друг друга; обнаруженный конфликт выносят на согласование и ждут решения пользователя перед зависимым действием.

**Fails-when:** проверка проходит только рядом с соседней папкой, ресурс доступен лишь на машине автора, процедура требует отсутствующую зависимость либо совместный контекст не проверен против своего лимита.

Сохраняй команды, результаты и ограничения приёмки. Структурная проверка не доказывает поведение агента или приложения; непроведённую проверку отмечай как непроведённую.
