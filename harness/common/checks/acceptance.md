# Приёмка независимости harness

Требования согласованы: 2026-10-04. Перенесены: 2026-10-05. Полная приёмка ещё не выполнена.
Объект: [структурный контракт](../rules/comm-package-independence.md).

| Режим | Условия проверки | Требуемый результат |
|---|---|---|
| Только common | В чистый временный проект скопирована только `harness/common/`; project отсутствует; исходное приложение не используется как зависимость | Собственный индекс работает, необходимые внутренние ссылки и ресурсы доступны, проверки запускаются; обязательных зависимостей на project/исходное приложение нет |
| Только project | В другой чистый временный проект скопирована только `harness/project/`; common отсутствует | Собственный индекс работает, процедуры и проверки доступны без файлов, скиллов и скриптов common |
| Оба вместе | В третий временный проект скопированы обе папки | Обе доступны; обнаруженный конфликт не разрешается молча; совместная загрузка соблюдает отдельно согласованный стартовый бюджет |
| Нарушенная комплектность | В изолированной копии удалён обязательный локальный ресурс или повреждена ссылка | Соответствующая проверка замечает повреждение и даёт диагностируемый отказ; зелёный результат на пустой выборке не считается доказательством |

Приёмка должна отдельно показать комплектность, подключение к Codex/Claude и поведение. Проверка существования файлов не доказывает чтение агентом, а успешный запуск инструмента не доказывает обязательность его запуска.
Ссылки на источники происхождения опыта не должны становиться скрытыми обязательными зависимостями установленной папки. Возможности и ограничения живого проекта проверяются отдельно от автономной работоспособности пакета знаний; отсутствие приложения в чистом временном проекте нельзя выдавать за успешную проверку его поведения.
Существующие глобальные скиллы автора или соседние каталоги не должны маскировать неполноту тестовой копии.
Формат подключения, внешние prerequisites и точные бюджеты ещё предстоит согласовать. Здесь зафиксированы требования пользователя, а не выбранная реализация.

## Состав проверок, уточнённый 2026-10-05

### Файлы и перенос

Для каждого из трёх режимов проверять все локальные Markdown-ссылки, пути к справочным файлам и ресурсам, команды и скрипты, требуемые инструкциями. Отсутствие ресурса, выход обязательной ссылки за границы пакета или зависимость от соседа должны давать ошибку. Пути назначения установки в корне нового проекта отличаются от ссылок на обязательные исходные ресурсы; установка не должна читать соседний или исходный пакет. Внешние URL проверяются отдельно и не служат доказательством локальной комплектности.

Чистые временные копии проверяются без доступа к исходнику и соседнему комплекту. Новый cwd и пустой HOME сами по себе не обеспечивают изоляцию на уровне ОС. Негативные контроли: повреждённая ссылка, отсутствующий ресурс, различающиеся зеркала, игнорируемый общий материал, неожиданная зависимость от глобального авторского скилла.

### Реальное обнаружение и применение

В каждом режиме запустить отдельно Codex и Claude Code в чистом окружении с установленными нативными копиями. Проверить уникальный тестовый скилл: наличие в списке, явный вызов и контрольное действие с использованием ресурса из его собственной папки. Автоматический выбор по description проверять отдельно; результат зависит от задачи и не заменяет явный вызов. Для правил отдельно проверяется загрузка обязательного ограничения до выбора процедуры и отсутствие обхода через индивидуальный материал.

Для каждого режима и агента сохранить версию, команду или способ запуска, наблюдаемый результат и ограничения. Невозможность запуска означает «не проверено». Совпадение файлов, validator или generic Plugin Eval не означают обнаружения нативным приложением. Установленные authoring skills и глобальные конфигурации не должны скрывать недостающие ресурсы.

### Начальный контекст

Отдельно измерить три режима: начальные обязательные указатели и ограничения, а также нативный каталог названий/описаний скиллов. Объём всех файлов пакета не является стартовым контекстом. Инструкции установки, подробности процедур и тела README.human.md не должны попадать в стартовую загрузку. Численные бюджеты и окончательный способ подключения ещё не согласованы.

## Уточнение технической копии и текущий объём проверки

Пользователь разрешил установочную копию проверки входов в project/checks. Это
не обязательная зависимость от common: проектная копия исполняется самостоятельно,
документы и знания не дублируются. Сравнение байтов выполняется при наличии обеих
копий; в отдельном пакете оно не проверено и не требует соседней папки.

Подтверждён [изолированный запуск входной проверки](entrypoint-portability-evidence.md)
в трёх режимах. Он не подтверждает полный перенос знаний, все команды и ресурсы,
реальную загрузку правил/скиллов агентами или соблюдение стартового токен-бюджета.
