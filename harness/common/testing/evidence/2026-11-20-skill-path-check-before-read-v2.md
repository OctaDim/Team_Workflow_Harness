## Что получил Codex до первого вызова

Восемь независимых сессий повторили прежние запросы с `$comm-retry-external-operations`. В каждой Codex CLI 0.166.0 добавил отдельное сообщение с ролью user и блоком `<skill>`, путём и полным текстом установленного файла. Блок предшествовал стартовой команде. Текст совпал с эталоном размером 1 329 байт и SHA-256 `62a3632dac09626f5e0567c32816e6134037e78db2823ee71631bbc84fd23edb`. В семи сессиях инструмент затем ещё раз вернул тело. В восьмой модель могла применить уже полученный текст. Отсутствие команды чтения в такой сессии само по себе не доказывает отсутствие скилла в контексте.

В восьми новых сессиях из запроса убрали только символ `$`. Явное имя, задача, стенды, модель и настройки сохранились. Отсутствие тела во входных сообщениях до первого вызова проверено в каждой записи. Состояние профилей между запусками не переносилось.

Номера относятся к записям диалога модели с инструментом. Для каждого случая сверены путь, содержимое и очерёдность вызовов. В ответах на потерю подтверждения агент учитывал неопределённость результата операции. В развёрнутом запросе оценивалось ограничение повторной отправки при задержке 12 секунд и остатке бюджета 8 секунд.

Самостоятельная проверка пути и выдача полного текста прошли в 6 из 8 контрольных сессий. Четыре сценария раннего чтения сохранили уже полученное содержимое после INDEX. Общая приёмка требует также соблюдения всего порядка старта. Например, в первом явном запросе common-only перечисление правил совмещено с двумя сравнениями файлов. В повторных common-only штатный аудитор не засчитал полное правило владения из команды `ls … && cat …`. Диалог содержит его полный текст, хотя обход каталога начался до предусмотренного перечисления. Подробные результаты сохранены по каждому прогону.

## Остальные проверки

Обе установки дважды прошли стартовую проверку. В common-only старт создал нейтральный project. В common+project проверены хеши уже существующих файлов. Перед вызовами сравнили SHA-256 канонической и установленной копий скилла. Нативные прогоны использовали gpt-6.2-sol с medium и доступом к стенду только для чтения.

Локальные контроли различили отдельные вызовы, команды с `&&`, команды с переводом строки и перекрывающиеся события. Два непересекающихся фрагмента восстановили точный текст файла. С кандидатом, подставленным по обоим путям в изолированном окружении, полный `pytest` из корня завершился успешно — 235 passed. Штатный plugin-eval 0.1.2 выполнил start, analyze и explain-budget. Для правила получены 298 слов, 2 302 символа, 576 оценочных токенов и A (100/100).
