20 ноября 2026 года. База кандидата — `dba9ead`. Патч применим к этой базе. В [архиве кандидата](../../inbox/2026-11-20-bootstrap-template-sync/candidate.zip) сохранены все девять изменённых файлов, полное дерево затронутого скилла с копиями и манифест SHA-256. В [архиве проверки](2026-11-20-bootstrap-template-sync.zip) сохранены четыре исходные трассы Codex CLI, фактически сгенерированные входы, результаты подготовки установок, отчёты аудитора и использованные тексты учебного сценария.

## Что определяет содержимое шаблонов

| Генерируемый материал | Источники и границы |
| --- | --- |
| Новый корневой `AGENTS.md` | На базе использовался литерал `BOOTSTRAP` в `checks/ensure_entrypoint_links.py`. В кандидате авторский каркас хранится в `harness/AGENTS.bootstrap.md.in`. Из корневого `AGENTS.md` берётся единственная поддерживаемая команда Python, включая вариант с `-B`. Из `harness/common/START.md` берётся раздел «Порядок чтения после START». Переносимый результат — `harness/common/base/AGENTS.bootstrap.json`. Блок ссылок формирует штатная проверка в установленном порядке. Личные настройки исходного входа в шаблон не переносятся. |
| Корневой `CLAUDE.md` | Генератор реализует фиксированный контракт общего правила владения входами — относительный импорт `@AGENTS.md`. Содержимое существующего входа не используется как образец для других проектов. |
| Нейтральный `harness/project` | Источники — `base/project-skeleton.json` и функция `create_project_skeleton`. Категории определяют строки INDEX и пояснения каталогов. Общие тексты START, вводной части INDEX и пояснения корня заданы генератором. Сгенерированные START и INDEX исходного нейтрального каркаса побайтно сверены с одноимёнными файлами исходной установки. Данные рабочего project не служат источником общего шаблона. |
| Конфигурация тестов | `harness/common/testing/pytest.ini` уже является самостоятельным установочным образцом. Существующий конфиг принимающего проекта сохраняет свои настройки. |

В авторском checkout обычный старт и штатный `harness/common/scripts/run_tests.py` пересчитывают переносимый шаблон при изменении его источников. Процедура подготовки коммита предписывает выполнить обычную проверку после такой правки и включить результат в тот же коммит. В принимающей установке авторский каркас отсутствует. Старт использует поставленный шаблон при создании входа. Синхронизация не требует Git-хуков или фонового процесса.

## Автоматические проверки

Полный прогон в изолированной копии кандидата через `python harness/common/scripts/run_tests.py` завершился с кодом 0, прошли 235 тестов. Три регрессии синхронизации также прошли отдельным запуском. Проверены изменение штатной команды, текста раздела START и самого каркаса, фактические имена обновлённых источников в сообщении, генерация из обновлённого пакета, сохранение настроек пользователя, отсутствие ложного сообщения и сохранение байтов и времени записи при несвязанной правке. При неверном поле каркаса команда вернула ошибку с путём несогласованного шаблона и сохранила последнюю полную версию.

## Сквозная проверка

В каждой свежей установке до запуска отсутствовали корневые AGENTS и CLAUDE. В common-only старт создал нейтральный project. В common+project все 21 файл существующего project, включая контрольный документ, сохранили свои байты. Повторный запуск сохранил сгенерированный вход и project. SHA-256 итогового `AGENTS.md` в обоих режимах — `666cf1f42d5cc463cce798448b6c95a1b0592f2ced5e94f0957b8e8c2d2651fb`.

Codex CLI, модель `gpt-6.2-sol`, отдельные профили, установка только для чтения. Во всех четырёх запросах передан ровно текст «Примени $comm-retry-external-operations к потере ответа после отправки документа». Тестовый START дополнительно ссылается на правило об учебной квитанции. Когда документ мог быть отправлен, оно требует отдельным вызовом прочитать `comm-delivery-check` до следующего правила. Запрошенный пользователем `comm-retry-external-operations` проверялся отдельно. Установлена одинаковая версия этого скилла из его заявки. События инструментов оценены штатным `assess_rule_reading`. В первом common-only Codex перешёл от INDEX к финальному ответу без инструментального чтения запрошенного файла. Во внутренних журналах всех четырёх сессий CLI уже приложил содержимое явно вызванного скилла к контексту на событии 14, перед первым вызовом инструмента на событии 17. Поэтому правильный ответ сам по себе не подтверждал порядок обращения к файлам. Уточнение в каркасе требует отдельного подтверждённого чтения, если его ещё не было в сессии. В итоговых прогонах ранний скилл и запрошенный скилл прочитаны каждый один раз. В обоих ответах Codex предложил сверить квитанцию и исходную операцию, сохранить неизвестный исход при неоднозначном результате и ограничить повтор гарантиями идемпотентности.

Проверка Codex по критериям BOOTSTRAP прошла в обоих режимах. Статус проверки Claude — «непроверенный». Итоговый статус кандидата — **непроверенный**.
