В обычных сценариях тестовая установка получила штатные AGENTS, CLAUDE, стартовую проверку, шаблон project и текст кандидата START с дополнительной ссылкой на учебное правило. В обоих режимах стартовая команда завершилась успешно. Следующей командой Codex совместил чтение START с перечислением и чтением правил. В трёх из четырёх трасс эта команда открыла также INDEX. Последующее правильное чтение не восстанавливает порядок предыдущих вызовов. В контроле изменился пользовательский запрос, который задал отдельные вызовы для проверки, обоих START и отдельных файлов. Кандидат правил был тем же. Обычная установка со своими существующими входами и два повторных запуска в изоляции сохранили файлы project.

В первой редакции Codex отложил применимую ссылку из уже прочитанного через START правила до чтения следующего. В редакции 2 момент перехода указан в START и правиле порядка. Тестовая установка с точной копией проектного входа показала более раннее нарушение порядка. В отдельном опыте при отсутствии AGENTS генератор в двух режимах воспроизвёл прежнее безусловное требование прочитать все правила до скилла. Уточнённая стартовая команда из [связанной заявки](../../inbox/2026-11-19-codex-explicit-skill-startup/request.md) также требует дождаться INDEX перед явно вызванным скиллом. Нужна согласованная редакция общего старта для обеих заявок.

## Проверка кандидата

Исходная база — `823637b`. В копии разместить START и оба правила из заявки по штатным путям, установив `comm-instruction-order-v2.md` под именем `comm-instruction-order.md`. Оба правила скопировать в `.claude/rules/`. Аудитор и тесты поместить в `harness/common/checks/` и `harness/common/testing/tests/`. В новых сценариях проверка получает ожидаемое условие из постановки конкретной задачи. Она сверяет владельца, полный текст, момент наступления условия и последовательность чтений. Шесть первоначальных регрессий воспроизвели отсутствие поддержки такого перехода. На окончательных файлах команда `python -m pytest . -q --tb=short` прошла 224 теста, а целевой файл — 30 тестов. Проверки охватывают 0, 2 и 12 правил через START, позднее условие, скрытые и вложенные пути, повтор, неполное чтение, просмотр имён файлов и массовое открытие тел. Шестистрочные отчёты доступны по индексам каждого вызова аудитора в JSON.

Нативная команда — `python3 harness/common/checks/check_human_guide_search.py harness/common/rules/comm-human-folder-guides.md --mode MODE --task TASK --output FILE`. Значения MODE — common и both, TASK — linked, history, read и search. Контрольную подсказку и исходные хеши трасс см. в JSON. Трассы разобраны повторно окончательным аудитором. В отдельных авторских сценариях добавление безусловной ссылки и снятие условия проверены в одноразовом учебном файле. После первого сообщения файл остался прежним. После подтверждения и возобновления с правом записи файл изменился. Два промежуточных недостатка проверочной оснастки — поиск вопросительного знака в просьбе «Подтвердите» и запуск продолжения в режиме чтения — исправлены при проверке того же диалога.

Уточнение помещено в существующие владельцы порядка и чтения. Переход должен состояться до выбора процедуры, поэтому отдельный скилл не решает задачу. Дополнительная пара правила со скиллом повторяла бы тот же порядок. Plugin-eval дал A для набора до и после. У правила чтения 295 слов, 2365 символов и 592 статических токена, у правила порядка — 261, 1965 и 492 соответственно. До изменения оценки составляли 577 и 453 токена. Обе редакции каждого правила укладываются в индивидуальные пределы. Замечание анализатора о суммарном размере двух файлов присутствует и в исходном наборе. Данные фактических чтений и использования CLI приведены для каждого прогона.
