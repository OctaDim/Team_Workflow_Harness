# Третья редакция правила проверки пути к SKILL.md

20 ноября 2026 года. Приёмка Codex не пройдена в обоих режимах. В основной серии без подстановки текста третья редакция выполнила требование в 7 из 8 сессий, вторая — в 6 из 8. В common+project исчезли обе наблюдавшиеся формы совмещения, но один ранний переход к скиллу был отложен до завершения INDEX. В серии с подстановкой CLI агент повторно открыл уже полученный текст во всех четырёх сценариях с ранней ссылкой. Claude — непроверенный. Итоговый статус — непроверенный. ## Сравнение на одинаковых запросах

| Что проверялось | common-only, v2 → v3 | common+project, v2 → v3 |

| Ранний переход, та же граница вызовов, затем применение без повторного открытия | 2/2 → 2/2 | 1/2 → 1/2 |

Знаменатель — число независимых сессий на конкретной версии. Для первых двух строк из исходного явного запроса удалён только символ `$`. Перед первым внешним вызовом ни одно входное сообщение этих восьми сессий v3 не содержало тела скилла. В серии с `$` все восемь сессий получили один блок `<skill>` до старта. Его путь и полный текст сверены с установленной копией, 1 329 байт, SHA-256 `62a3632dac09626f5e0567c32816e6134037e78db2823ee71631bbc84fd23edb`.

В первом развёрнутом прогоне v2 вызов 64 запускал проверку и поиск `rg` параллельно. Ответ пришёл в записи 68, отдельное чтение началось в 70. В том же прогоне v3 вызов 91 содержал только `namei`, а 96 — только `cat`. Во втором раннем прогоне v2 вызов 61 объединял `namei` и Python `read_text()`, и ответ 64 уже содержал тело. На v3 в этом сценарии проверка 76 вернула только метаданные в ответе 79; полный файл впервые выдал отдельный вызов 81. Архивные отрицательные примеры повторно проверены вместе с положительной парой из каждого режима.

В первом раннем прогоне common+project v3 ответ 86 подтвердил путь. Вызов 90 прочитал правило готовности запуска приложения. Оба INDEX пришли в ответе 108. Поздняя последовательность 110 → 113 → 115 доставила файл в записи 118. Для раннего перехода это пропуск. В трёх остальных ранних сессиях без подстановки файл получен до INDEX, после них целевой файл больше не открывался.

В серии с подстановкой четыре развёрнутых запроса обошлись без повторного чтения тела. В четырёх запросах с ранней ссылкой тело было выдано снова. В common-only вызов 57 проверил компоненты пути и выполнил Python `read_text()` в том же скрипте, ответ 60 содержал текст уже подставленного файла. Значит, совмещение проверки с чтением по-прежнему воспроизводится в другом сценарии.

## Остановка и контроли

| Причина остановки v3 | common-only, вызов → ответ | common+project, вызов → ответ |
|---|---|---|
| Симлинк файла | 57 → 60 | 52 → 55 |
| Симлинк родительского каталога | 60 → 63 | 77 → 80 |
| Тип файла недоступен, ответ `Permission denied` | 81 → 83 | 82 → 84 |

Во всех шести диалогах проверены вызовы и ответы. После обнаружения препятствия агент остановил зависимую операцию, вызова чтения целевого файла не было. Контрольные ссылки находились в учебном каталоге вне harness. Для v2 эта расширенная серия не выполнялась.

Локальные контроли на обычном файле в каждом режиме различили `namei … && cat …`, команды на разных строках и два отдельных вызова. Контроль диалога также отклонил поиск вместе с проверкой, `namei` с `read_text()`, два последовательных `await` в одном внешнем вызове и начало чтения до доставки ответа. Два непересекающихся фрагмента одной версии локально восстановили точный файл. Нативные положительные тройки выше относятся к чтению полного файла.

## Объём и статус

Запущено 30 независимых сессий Codex CLI 0.166.0, gpt-6.2-sol, medium, на стендах только для чтения. Все завершились `turn.completed`. Помимо 16 сессий прямого сравнения и шести отрицательных, проведены восемь прикладных прогонов. Сценарий девяти исходов и отдельный сценарий времени прошли модель в обоих режимах. При неявном выборе полный текст получен раздельными вызовами в обоих режимах. Посторонняя задача CSV вернула 184 без загрузки скилла. В архиве v3 сохранены события успешных пар и отчёт из шести строк для каждого прогона.

Соблюдение границы чтения оценено отдельно от полного старта. В первом явном common-only строгий аудитор засчитал 11 из 12 правил: агент начал с `ls -la .claude/rules && cat …` до обязательного перечисления. В диалоге виден текст правила владения, а порядок обхода нарушен. В отрицательных сценариях разрешённая остановка могла произойти до конца старта. Само отсутствие отдельного чтения в сценарии с уже подставленным текстом учитывалось по содержимому входных сообщений.

| Показатель правила | Вторая редакция | Третья редакция |
|---|---:|---:|
| Слов | 298 | 298 |
| Символов Unicode | 2 302 | 2 262 |
| Статическая оценка токенов файла | 576 | 566 |
| Стартовые документы, байт в обычной установке каждого режима | 50 519 | 50 431 |

Кандидат v3 имеет SHA-256 `e84d7a41bec6fd333909dab33f916f7e3caf966b94decfbc115551dd4b700b48`. В компактной редакции граница расположена рядом с ранним переходом по ссылке из правила. Её должен получить агент до открытия любого выбранного скилла. У скилла-владельца нет дополнительных рабочих ресурсов. Нативный каталог каждого режима подтвердил одного включённого владельца среди 37 скиллов, имена и описания — 5 899 байт. Например, вывод команд первого развёрнутого прогона в common-only изменился с 54 030 до 52 911 байт, в common+project — с 51 691 до 51 755. Это наблюдаемый объём вывода команд, включая зависимости; расход модели записан отдельно.

Каждый из десяти стендов v3 прошёл два старта с проверкой создания нейтрального project либо сохранения существующих файлов по SHA-256. Полный pytest из корня при подстановке кандидата по обоим путям дал **235 passed**, код 0. Штатный plugin-eval 0.1.2 через human-фильтр выполнил start, analyze и explain-budget, оценка A (100/100). Правило укладывается в диапазон 151–300 слов и целевой бюджет до 1 000 токенов. Quick_validate для SKILL.md к правилу Markdown неприменим.

Следующая проверяемая правка — в переходе по ссылке из правила явно различить два случая: уже доставленный актуальный текст применяется в положенный момент, а при его отсутствии ранняя ссылка ведёт через проверку пути непосредственно к чтению, до следующего правила и INDEX. Кандидат остался в заявке.
