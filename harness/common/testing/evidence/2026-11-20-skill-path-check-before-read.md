# Проверка пути перед чтением SKILL.md в Codex

20 ноября 2026 года. Кандидат `85d69415` не прошёл приёмку Codex в обоих режимах. На сценарии девяти исходов агент дождался результата проверки пути и следующим вызовом получил весь файл. В сценарии раннего чтения он повторно открыл неизменную копию того же владельца. Claude — непроверенный. Итоговый статус — непроверенный. Каноническое правило и установленная копия остаются на версии `ec21f310`. [Заявка и кандидат](../../inbox/2026-11-20-skill-path-check-before-read/request.md)

В основной матрице базовая версия не подтвердила раздельную проверку и первое чтение ни в одном из четырёх запусков двух исходных запросов (развёрнутый и девять исходов × два режима). Кандидат подтвердил три из четырёх. Результат повторного явного вызова различался между независимыми сессиями.

**Первое чтение.** SHA-256 целевого SKILL.md — `62a3632dac09626f5e0567c32816e6134037e78db2823ee71631bbc84fd23edb`, размер — 1 329 байт. В повторе сценария девяти исходов в common-only результат проверки записан в строке 99 журнала диалога с инструментом, вызов чтения — в строке 101, точный текст — в строке 104. В common+project это строки 94, 96 и 99. В каждой первичной сессии с девятью исходами решения прошли модель 9/9. Сценарий тайм-аута дал 2 секунды на попытку, 3 секунды задержки и 0 новых отправок после отмены на обеих версиях в обоих режимах.

**Пропуск и повтор.** У кандидата в первичном развёрнутом common+project результат проверки пути — событие CLI 37, поиск — 39, SHA-256 — 43. Ни один ответ команды не содержал полного текста владельца. У кандидата в первичном common-only с ранней ссылкой ответы 31 и 43 побайтно равны одному SKILL.md. В подробном повторе common+project с ранней ссылкой строки 62 и 77 содержат тот же полный текст. У базового правила в первичном common-only с ранней ссылкой обе операции были совмещены в событии CLI 35.

**Сверка источника.** В исходном архиве common-only событие 37 развёрнутого запроса отделяет `namei` от `cat` переводом строки внутри одной команды. Событие 35 с `&&` принадлежит сценарию девяти исходов (`actions`). В отдельном сценарии `timer` событие 35 содержит INDEX, 37 — уже текст скилла, 39 — проверку пути. В текущей матрице все три запроса взяты из архивного `results.json` без изменений. [Исходные трассы](2026-11-20-external-retries-after-explicit-skill-rule.zip)

## Установка, объём и метод

Базовое правило из коммита `07d8ffe` имеет SHA-256 `ec21f31034c39b90d9c496c559b2cce831acb392e98dea2bff59a61ee0da4591`, кандидат — `85d69415ce8cb02a64d366c628b51f08c6414924043b94d9ffa37f34ae9a0304`. В 20 изолированных стендах две версии одного правила установлены в каноническую и нативную папки. Два последовательных старта каждого стенда подтвердили создание нейтрального project и сохранение существующего project по хешам. Учебные ссылки и недоступный каталог размещены вне дерева harness. В отрицательных сценариях условное учебное правило требует проверить путь. В сценарии повторного использования правило срабатывает до INDEX. Правило порядка чтения должно работать до получения тела скилла. Уточнение принадлежит существующему правилу, а перенос этой границы в новый скилл потребовал бы сперва открыть его.

В каждом каталоге `skills/list` подтвердил одного включённого владельца. У целевого скилла нет дополнительных рабочих ресурсов. Вывод команд включает зависимости и повторы; расход модели по сессиям записан отдельно в JSON. Штатный plugin-eval 0.1.2 через `plugin_eval_without_human.mjs` выполнил `start`, `analyze` и `explain-budget` для каждой версии. Обе получили A, 100/100, без обязательных и рекомендуемых исправлений. Словесный диапазон 151–300, целевой бюджет до 1 000 токенов. Кодового покрытия у Markdown нет, профиль quick_validate для SKILL.md к изменённому правилу неприменим.

**Объём проверки.** Codex CLI 0.166.0, gpt-6.2-sol, medium, чистый профиль, стенд только для чтения. Основная матрица — 36 независимых сессий, по девять сценариев на версию и режим. Ещё 16 сессий на четырёх сценариях сохраняли диалог модели с инструментом для проверки последовательности внешних вызовов. При разборе первичного JSONL отсутствие результата команды означает пробел в свидетельстве. Например, отрицательный ответ инфраструктуры виден в подробном диалоге, хотя может отсутствовать в списке команд CLI. Успех повтора учитывается отдельно от первого результата.

Локальные контроли использовали реальные ответы команд для безопасного файла, обе формы совмещения, раздельную пару и чтение по непересекающимся фрагментам той же версии. Проверка пересечения интервалов событий была синтетической. Частичное чтение проверено локально. В первичных и дополнительных нативных прогонах проверялось чтение полного файла. Полный `python -B -m pytest -q -p no:cacheprovider .` из корня, pytest 8.4.2 — 235 passed на базе, 235 passed с кандидатом, код 0 в обоих случаях.

В архиве находятся исходные CLI JSONL, выбранные поля записей вызовов из подробных сессий, точные запросы, сценарии, команды, хеши, разбор результатов, шесть строк учёта правил для каждого прогона и протоколы pytest. При остановке на запрещённом пути отчёт отдельно показывает достигнутую границу старта. [Архив проверки](2026-11-20-skill-path-check-before-read.zip)
