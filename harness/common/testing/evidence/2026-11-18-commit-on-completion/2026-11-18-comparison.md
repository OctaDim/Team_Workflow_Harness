# Проверка вызова процедуры коммита при завершении работы

Дата — 2026-11-18. Исходный Git HEAD — `83c7c65`. В сессиях использовано
текущее рабочее дерево после публикации инструкции о зависимостях скиллов.
Основные задания не упоминали Git, коммиты или скилл коммитов. Для обычной
задачи был выбран простой маршрут, для очереди — штатная процедура INBOX.
В каждый одноразовый репозиторий заранее добавлено постороннее staged-изменение.
Codex CLI 0.166.0 запускался вне основного репозитория, в bwrap, с доступом
на запись только к тестовой раскладке. Для `ce-commit` использовано
неизменённое тело установленного скилла Compound Engineering 3.38.0,
размещённое в нативном каталоге тестовой раскладки.

## Что сравнивали

Исходные инструкции сравнили с [полными папками кандидата](../../../inbox/2026-11-18-commit-on-completion/candidate-skill-routing/).
Кандидат уточняет описание скилла коммитов, вызывает его после закрытия
каждой заявки INBOX и разрешает требуемый `ce-commit` в простом маршруте.
Его проверяли без нового постоянно загружаемого правила. SHA-256 изменённых
`SKILL.md`:

| Скилл | SHA-256 |
|---|---|
| comm-commit-task-stages | `2648cc8138bd20eff59542618a31eedc1aa71e27f61b585bf94f00a06094df82` |
| comm-process-harness-inbox | `a038a933e4eb96519807505a502b7e8f1289b94b15bc942057b8aa33468cf60d` |
| comm-select-development-workflow | `be913f2f0cbbbbd13b1f6c82f70c9088e12e0d3938c118a8f34f0bac8aacfb1d` |

Постоянное правило уместно, если пропуск вызова сохраняется после уточнения
контекстных процедур. Только правило потребовало бы дублировать существующие
условия готовности и безопасной работы с индексом. Пара из короткого правила
и действующего скилла имела бы проверяемую пользу при таком пропуске.
В этих прогонах пропуск не воспроизвёлся, поэтому пару не испытывали.

## Поведение Codex

Каждая строка проверена отдельно в common-only и common+project.
Сверены команды, чтение полных тел и зависимостей, фактический порядок
записи результатов, дерево каждого коммита и состояние индекса.

| Сценарий | Исходная установка | Кандидат со скиллами |
|---|---|---|
| Обычная задача с двумя связанными правками | Один коммит в каждом режиме | Один коммит в каждом режиме |
| Две заявки INBOX | Два коммита в каждом режиме, первый перед записью второй заявки | Два коммита в каждом режиме, первый перед записью второй заявки |
| Только чтение | Не прогонялся | Ноль коммитов, скиллы коммита не загружались |
| Незавершённый черновик | Не прогонялся | Ноль коммитов, черновик записан |
| `.git` только для чтения | Не прогонялся | Ноль коммитов, названа ошибка `.git/index.lock`, обе правки сохранены |

Во всех 14 прогонах чужой staged-файл сохранил исходную запись в индексе.
В восьми штатных прогонах с коммитами оба скилла коммита были прочитаны.
В итоговых ответах этих восьми прогонов есть сокращённые хеши, заголовков
нет. Заголовки и списки файлов подтверждены в Git. В двух прогонах очереди
на кандидате временные файлы сообщения создавались внутри `.git`, хотя
`ce-commit` просит размещать их вне репозитория. Это отклонения от
оформления и процедуры, даже при правильном составе коммитов и индексе.

## Установка и бюджет

`quick_validate.py` принял три пакета. В каждом режиме полные папки
кандидата совпали в каноническом и обоих нативных размещениях. Два старта
прошли, состояние project сохранилось, целевые тесты правил и структуры
дали по 6 успешных тестов. Запрос `skills/list` вернул по одному активному
владельцу трёх скиллов и `ce-commit` в `.agents/skills`.

В каждом режиме 17 стартовых файлов занимали 47 161 UTF-8 байт. Метаданные
37 скиллов выросли с 6 641 до 6 663 байт. Node 22.14.0 и установленный
Plugin-eval 0.1.2 через `plugin_eval_without_human.mjs` выполнили
`start`, `analyze`, `explain-budget` и `compare`.
Статические токены указаны в порядке «метаданные / тело / ресурсы».

| Скилл | Исходная версия | Кандидат | Оценка |
|---|---|---|---|
| comm-commit-task-stages | 44 / 391 / 339 | 49 / 444 / 339 | A (100) |
| comm-process-harness-inbox | 34 / 359 / 1171 | 34 / 435 / 1171 | A (95) |
| comm-select-development-workflow | 34 / 218 / 1190 | 34 / 252 / 1190 | A (95) |

Два предупреждения о тяжёлых условных ресурсах присутствовали в исходной
версии. Ресурсы сохранили байты и остаются в диапазоне heavy до 1200.
Кодового покрытия для Markdown-пакетов нет. В трассировках отдельно
записаны фактические чтения и счётчики CLI. Например, для обычной задачи
входные токены с кэшем составили 524 437 → 237 521 в common-only и
494 862 → 430 504 в common+project. Эти одиночные прогоны не устанавливают
типичную экономию токенов.

| Агент | common-only | common+project |
|---|---|---|
| Codex | Сценарии вызова и состояние Git проверены, найдены отклонения процедуры | Сценарии вызова и состояние Git проверены, найдены отклонения процедуры |
| Claude | Не проверено | Не проверено |

что для вызова необходимо постоянное правило. Кандидат остался в INBOX.
