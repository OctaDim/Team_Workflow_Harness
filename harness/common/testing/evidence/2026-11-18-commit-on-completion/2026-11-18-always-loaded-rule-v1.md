# Проверка постоянного правила о локальном коммите

Дата — 2026-11-18. Проверена [версия 1](../../../inbox/2026-11-18-commit-on-completion/candidate-rule-v1/comm-task-commit-on-completion.md).
SHA-256 — `a15e372a37b16c7c440eaed5fcffae55e8b898155137d76fc836b65834893477`. Целевые размещения —
`harness/common/rules/comm-task-commit-on-completion.md` и
`.claude/rules/comm-task-commit-on-completion.md`.

Правило задаёт момент вызова уже действующего `comm-commit-task-stages`
перед итоговым ответом по завершённой задаче с изменениями и перед
переходом к следующей заявке INBOX. Процедура коммита остаётся в скилле.
Простой маршрут допускает требуемый им `ce-commit` для локального коммита.
Условия проверки результата и достаточности разрешений сохранены.
В [предыдущем сравнении](2026-11-18-comparison.md) контекстные скиллы
вызывались без правила, но итоговые ответы пропускали заголовки коммитов.
Отдельное правило устраняет этот наблюдаемый пробел в испытанных сценариях.

## Нативное поведение

18 свежих сессий Codex CLI 0.166.0 в одноразовых Git-репозиториях,
по девять на режим. Основные задания не называли коммит, Git или скилл.
Во всех прогонах прочитан полный текст правила из `.claude/rules` и
сохранена исходная запись чужого staged-файла. Проверены Git и трассировки,
а не только ответы агента.

| Сценарий | Результат в common-only и common+project |
|---|---|
| Обычная завершённая задача с двумя правками | Прочитаны `comm-commit-task-stages` и `ce-commit`, создан один коммит только из двух нужных файлов, сообщены хеш и точный заголовок |
| Две самостоятельные заявки INBOX | Создано по коммиту на заявку, первый до записи второй заявки, сообщены оба хеша и точные заголовки |
| Только чтение | Ответ получен без коммита и без чтения скиллов коммита |
| Незавершённый черновик | Черновик сохранён без коммита |
| Репозиторий с `.git` только для чтения | Названа ошибка создания `.git/index.lock`, обе правки сохранены |
| Обязательный скилл отсутствует | Указана недоступная зависимость, обе правки сохранены, коммита нет |
| Два владельца с одинаковым именем скилла | Указана неоднозначность, обе правки сохранены, коммита нет |

Изначальная формулировка изоляции задания ограничивала работу каталогом
тестового репозитория. В первых прогонах агенты использовали для сообщения
файл в `.git` или stdin. Четыре повторных положительных прогона уточняли
доступность изолированного `/tmp` для временных файлов, не меняя задание
и байты правила. Во всех шести коммитах повторов сообщения переданы через
отдельные временные файлы вне репозитория. Хеши, заголовки, состав и порядок
коммитов снова совпали с ожидаемыми.
