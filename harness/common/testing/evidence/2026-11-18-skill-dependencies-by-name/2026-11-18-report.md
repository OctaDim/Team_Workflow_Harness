`harness/common/scripts/plugin_eval_without_human.mjs` выполнили `start`,
`analyze`, `explain-budget` и `compare` для v2. Валидация профиля через
`quick_validate.py` на Python 3.12.3 прошла.

Статические верхние границы moderate составляют 92, 480 и 520 для первых
трёх измерений. Диапазон heavy условных ресурсов заканчивается на 1200.
Предупреждение `deferred_cost_tokens-budget-high` присутствовало уже
в базе. Пробное сокращение добавленного абзаца сохранило предупреждение и
убрало явное указание искать среди установленных скиллов. Версия 2 уточняет
область применения после поведенческого сбоя. Кодовых файлов в скилле нет,
поэтому `coverage-artifacts-unavailable` неприменимо. Ошибок Plugin-eval нет.

Временные установки базы и v2 имели одинаковый стартовый контекст по
файлам. Это 17 стартовых файлов на 46 073 байта и 36 пар имени и описания
на 5 732 байта. Каждый режим дважды прошёл стартовую проверку. В common-only
появился нейтральный project. В common+project сохранился зафиксированный
проект. Две проверки отсутствующих START и проверка project-only получили
ожидаемый отказ с кодом 2, без изменения исходных файлов. В каждом режиме
прошло по шесть тестов правил и нативных копий. В рабочем дереве
`python -B -m pytest -q -p no:cacheprovider .` на pytest 8.4.2 дал 195
успешных тестов. Конфигурация исключает два дерева inbox.

## Нативные сценарии

Codex CLI 0.166.0 подтвердил активную копию скилла в `.agents/skills` через
`skills/list` в обоих режимах. В контрольных прогонах действующей версии
Codex указывал путь к другому скиллу в примере правила. В исходном кандидате
common+project тот же сбой повторился при правильном переходе из скилла.
Версия 2 явно распространила поиск по имени на оба вида инструкции.

- При обычном и явном вызове в обоих режимах Codex полностью прочитал тело
  целевого скилла и `references/content-contract.md`. После этого он прочитал
  один установленный `comm-check-report-source-test`, применил его к
  синтетическому отчёту и получил контрольную отметку. В обоих фрагментах
  инструкции он использовал точное YAML-имя и условие применения.
- При отсутствии установленного скилла Codex сообщил о причине и не выдал
  отметку. При двух владельцах с одинаковым YAML-именем назвал обоих и
  остановился до выполнения любого варианта. Обе проверки прошли в каждом
  режиме.
- На несвязанном запросе Codex вернул `377`. Тело и ресурс целевого скилла
  не читались.
- В первом прогоне common+project ссылка из предложенного фрагмента
  включала префикс `author-draft/`. Запрос указывал путь шаблона от корня,
  не задавая файл вставки. В двух дополнительных прогонах запрос назвал
  точный файл вставки `author-draft/SKILL.md`. Codex в обоих режимах
  использовал `references/report-template.md`, и ссылка разрешилась из
  этого файла. Собственные ссылки проверяемого скилла разрешались во
  всех положительных сценариях.

Матрица фиксирует 10 основных прогонов и два дополнительных контроля на
точных байтах v2. Во всех 12 код выхода 0. Сводка содержит фактические
чтения полного тела и условного ресурса. Полные трассировки содержат команды
