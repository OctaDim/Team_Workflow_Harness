# Check current harness duplicates

Inputs: proposal, target harness/scope, canonical files, request statuses.

1. Inspect applicable current canonical rules, skills and resources. Identify owners;
   preserve higher-priority instructions and explicit user decisions.
2. Filter request statuses before reading bodies. Compare only relevant, current,
   unfinished proposals. Unknown status/currency stays uncertain; age proves neither.
3. Exclude completed, closed, rejected and superseded requests from routine checks.
   They are history, not current requirements; never revive replaced decisions.
4. Consult history only when necessary for a specific discrepancy. Explain why;
   verify claims against current canonical files and subsequent relevant decisions.
5. For stale/overlapping open requests, show the discrepancy and proposed resolution;
   wait for explicit user agreement. Never automatically close, edit or delete requests.
6. Report checked current owners, relevant open requests/statuses, overlaps and
   uncertainties. Explain any historical lookup; omit history-wide census counts.

Done: a supported duplication assessment or explicit unresolved questions.
Request execution, authoring and evidence retain their existing procedures.
