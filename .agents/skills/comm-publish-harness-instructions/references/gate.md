# Решение о публикации

Для текущей заявки, точных хешей файлов и мест установки собрать отчёт. По каждому клиенту (Codex, Claude Code), режиму (common-only, common+project) и обязательному сценарию записать ожидание, факт, результат «пройден», «не проверен» или «не пройден», причину и оставшиеся пробелы. Показать пользователю отчёт до запроса разрешения. Изменение версии сбрасывает результаты её проверок и требует нового согласования набора.

«Не пройден» означает обнаруженное расхождение: разъяснить ошибку, исправить в разрешённом объёме и повторить обязательные проверки. Конфликт поведения защищённых входов вынести на явное решение. При недоступной проверке пользователь может в той же INBOX-заявке явно разрешить публикацию именно перечисленных версий с перечисленными пропусками, включая защищённые входы. При неоднозначности уточнить и ждать. Сохранить фактические статусы даже после публикации. Прямое копирование из INBOX в рабочие папки запрещено, в том числе по просьбе скопировать новую версию без публикации.

Для связанного набора зафиксировать точные пути, прежние и новые хеши, отчёт и ссылку на явное решение пользователя. Канидат INBOX и переданный параметр команды сами не являются решением. Сначала перенести одобренные источники в канонические папки, потом синхронизировать назначения из канонических файлов. При прерывании возобновить тот же набор в той же заявке. При третьем значении пути остановиться. Проверить весь набор и свежий старт, сохранить постоянные свидетельства и обновить статус заявки. Разрешение для другого набора, клиента или пропуска не переносить.
